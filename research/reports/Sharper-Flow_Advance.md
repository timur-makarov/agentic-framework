## 3. Challenges

- **Bash plus files as runtime.** Files won; bash is less clear. Advance spent four months on Temporal, then replaced it with JSON and locks. `docs/rca-temporal-stale-projection-reads.md` records writes that timed out but landed, and evidence lost while the doctor reported healthy. VERIFIED. Verdict: keep files and git. Move JSON and typed logic to python3, already a dependency. Do not add a service.
- **Three lanes.** Advance sends everything through seven gates, with `/adv-task` as a shortcut. Its own audit (`docs/audits/agent-workflow-evidence-2026-07.md`, Q3) finds approval and review waits exceed execution. Verdict: the framework is right to have lanes, but the lane must be computed.
- **Review limited to changed lines.** Advance reviews against contract rows, not lines. Verdict: Advance is right. Changed-line binding should classify findings (in diff, adjacent, elsewhere), never delete them. A finding outside the diff needs a disposition.
- **A human accepts every ticket.** Neither is right. Advance has eight checkpoints, and only one is coded: `userApproved: true`, a boolean the agent passes (`tools/gate.ts:979`). Passing `actor` "user" bypasses the boundary check (`tools/gate.ts:1287`, `:1670`), and approvals are free strings. This is the same forgery gap as `protect.sh:161`. Verdict: approval only counts if it comes from a channel the agent cannot write: a PR approval, a signed commit or an out-of-band token. Everything else should be policy: computed LOW auto-accepts, which also gives unattended mode.
- **Reviewer proof.** Advance does not solve the framework's top gap. `adv_subagent_report_submit` receives only `(args, store)` (`tools/subagent-report.ts`, tool at `:1168`), and `agent` is a payload field. The root orchestrator can therefore submit a report saying `adv-reviewer`. INFERRED from the code path; not run. Role firewalls derive from session ancestry (`tool-role-firewall.ts:1-12`), which is the right idea, but it restricts tool access and never stamps authorship. Verdict: make Mode B the default, or have the gate record the reviewer run itself.
- **Copy-in distribution.** Advance installs globally, leaving `project.json` and `.adv/` in the project. The split is cleaner, but gate state then lives outside the repo, so CI cannot re-check it. Verdict: hybrid. Versioned, hashed framework files, with evidence committed in the repo.
- **One hook set for three tools.** Advance's deep integration gives it session ancestry and compaction hooks, at the cost of being locked to one host, requiring Node 24, Bun and pnpm, and a dedicated SDK parity check. Verdict: the framework is right. Host depth should be optional adapters.
- **18 skills, long AGENTS.md.** Advance shows the end state: `ADV_INSTRUCTIONS.md` is 104KB and the prompt floor baseline is 233,453 bytes across 44 files (`.opencode/prompt-floor-baselines.json`). Its later work removed things (`cutAgentToolsUnder20`, `consolidateAdvToolSurface2`, `retireInvestmentGovernanceDeadweight`). Verdict: the framework is on the right side, and should go further. Its better idea: procedure returned by the tool on demand (`_phasePlan.directive`, `.opencode/command/adv-review.md`), which `gate.sh next` could do instead of some skills.
- **Selftest as main proof.** A strong counterexample. 126K lines of tests, a mocked SDK (`AGENTS.md`), and a "spec law" system still lost a must-level rule, because its tests were deleted with the code that implemented it. `adv_change_close` also destroyed records, and a spec would have repeated that at scale (fixChangeCloseDataLoss summary). Verdict: mechanics tests do not prove guarantees. Keep a short attack suite (forged report, weakened check, lowered tier) that must keep failing. Each guarantee in the README should name its attack test.

## 4. Delete or simplify

- **Mandatory lessons.** Advance's audit shows 0 reuse hits in 14 readable reflections and 273 of 291 agenda items pending. Caveat: the counter is only a word-overlap heuristic (`tools/reflection.ts:338`), so this is weak evidence, but nothing shows value. Make lessons optional unless they produce a test, a rule or a hook. This could also shrink `memory-lint.sh`. INFERRED.
- **Regex shell guarding as a security claim.** Advance's tokenizer accepts variable indirection as a known gap (`rq-twf01.7`, `tools/trunk-write-firewall.ts:389`), and it needed a false-positive fix as late as `a3bb7b7f`. Keep `guard.sh` to a few irreversible denies, and rely on diff checks at ship.
- **Duplicate checks.** Advance's rule in `docs/redundant-defense-in-depth-agent-latency-prep.md` is good: a second layer is allowed only at a different trust boundary. Apply it when reviewing hooks against gate re-checks.
- **Dead config.** Delete `tracker`, `exception_max_days` and `models.*` from `.agentic/config.yml`, as Advance removed "investment governance".
- **Do not add gates.** Proposal, discovery, design and planning as separate gates add waits with little proven benefit. Keep one ticket. Add contract IDs inside it instead.

## 5. Orchestration

- Standalone and plug-in surfaces can share one core. Advance has host tools for mutation, a 13-tool read-only MCP server, and a disk-only `bin/adv` CLI with `--json` (`docs/runbooks/adv-mcp-code-mode.md`, `bin/adv:149`). The lesson is that reads should need no running agent. A `gate.sh next --json` is the minimum, and an MCP server is optional.
- `degraded` and `operator_required` are useful result states. They tell an orchestrator to stop retrying.
- `docs/rca-archive-merge-authority-gap.md` is the best lesson. The prompt said archive sign-off does not grant merge, while the tool armed auto-merge anyway. Authority must live in one place in code, and be exposed as data the orchestrator can read.
- Squash merges broke its "was this merged" proof (ROADMAP #202, ADR 0010). The framework closes tickets on the branch, so check how it behaves under squash. ASSUMED risk; I did not test it.
- `docs/ten-agent-concurrency-evidence.md` is a fine pattern: generated evidence from 10 real processes with no model. It tests one host only.
- External state does not help orchestrators using separate hosts. For those, keep state in git refs and committed files.

## 6. Do not copy

- Any code: license unconfirmed.
- Self-attested authority: `userApproved`, `actor: user`, `approvalEvidence`, `target_confirmed`.
- Prose-only protection of state. "Never read ADV state files directly" lives in a global instruction file (`.opencode/agents/adv.md`). The firewall allows non-git targets (`tools/trunk-write-firewall.ts:278-286`), so `change.json` is writable by shell. INFERRED; not run.
- `adv_conformance run` reads a local artifact path chosen by the caller (`tools/conformance.ts`, `artifact_path`). The "outside the agent's reach" claim depends only on a role check at the execution gate.
- Spec-as-law machinery: 24 spec files and requirement IDs across code did not stop a must-rule from dying. `force: true` re-mint also exists (`tools/contract.ts:223`), and I found no gate comparing the agreement with the mint hash.
- Template pollution: 450 archive folders and 58MB in `.adv`, plus `temp/`, `.firecrawl/`, and rules that depend on files in `~/.config/opencode`.
- Self-hosting a tool on itself with a deploy gap: its fix "is inert until deployed".
- Overbuilding: epics, portfolio triage, competitor scans, cross-project targets.
- Suspicious content: a narrow grep of `.opencode`, `skills` and the instruction files found no injection text. I did not read `.firecrawl/` scrapes.

## 7. If you rebuilt the framework

Keep the core: scripts own state, files plus git, one `next` command, and the small hook set. Change the shape around one proof chain: the ticket holds a contract with numbered items, the lane is computed from the diff and recomputed at ship, the script records every run in a committed ledger, the gate itself launches the reviewer and records that it did, each contract item needs one review row, and each finding needs a typed disposition. Human approval comes only from a channel the agent cannot write. `next --json` returns a closed set of states with codes. Each stated guarantee has an attack test. Advance's main lesson is about restraint: it built all of this and more, and its strongest guarantees still rested on what the agent claimed.
