# Changelog

One line for each change, saying why.

- Add the engine in Python 3.11 with the standard library only: the first-match table, the verbs add, accept, next, advance, status, context and drop, state derived from git and the journal, claims with their own worktrees, and the local squash merge, so a ticket can run from add to merge.
- Add bin/rail, the launcher that runs the engine next to it and stops with one line on Python older than 3.11.
- Add the end-to-end railroad tests on fixture projects (tests/), so every rule is checked through the real launcher: run with python3 -m unittest discover -s tests.
- Leave branches named like tickets but holding no ticket file alone and list them in status, because such branches are the person's to deal with.
- Make next --ticket NN run a failed setup again, read open ASSUMED rows from the worktree's copy of the ticket, and skip tickets next can't act on before deriving them again, so the briefs match what the agent sees and next stays fast.
- Show leftovers in the text output of next, advance and drop, so a person reading the terminal sees what was left for them.
- Split the framework into engine/ (copied into a project by rail init) and seed/ (copied once), so a project owns its engine and its starting files.
- Add install, which links rail into ~/.local/bin, and make bin/rail hand over to the project's own .rail/bin/rail, so a project's changes to its engine take effect.
- Add rail init: it copies the engine and seed, writes .rail/bin/rail and .rail/SOURCE, appends the ## Rail section to AGENTS.md, imports it from an existing CLAUDE.md, merges .claude/settings.json, adds the rail workflow and .gitignore lines, and never overwrites a project's file.
- Make the first rail next return the init task until the project's config is on its base branch, so the agent proposes setup, verify, areas, risk paths, rules and .worktreeinclude for the person to confirm.
- Add rail doctor, the SessionStart hook (PATH through CLAUDE_ENV_FILE and a snapshot of this session's ticket), and rail ci with the rail workflow, so CI repeats the ship checks and fails with "not shipped yet" before ship.
- Add the gate-launched review: advance runs review.command in the ticket's worktree with the brief on stdin, checks the review/v1 output, binds each run to the patch-id, keeps the runs in NN-review.json and resets the worktree, so a review can't be skipped or hand-written.
- Add the findings ledger with rail answer, a refuter for disputed blocking findings, and the HIGH security seat with a refuter for each blocking finding, so every finding ends fixed, declined with a reason, or parked.
- Freeze the contract and tier at acceptance and add rail amend, so a weakened check or a lowered tier fails at ship until it is amended (and, for a changed Done Contract outside auto tiers, approved).
- Add retry budgets and the consult pack: at the budget a different model advises once, then a person takes over; rail accept continues any wait with a note for the agent's next brief.
- Add structure rules on added lines and files (with the default rule), size caps that raise the tier, and the migration brief, so a bad shape or an oversized change is caught at ship and in CI.
- Make rail ci check the frozen contract and a complete review for the patch, and add a stand-in reviewer to the tests so the suite never calls a model.
- Add the guard hook's deny rules for force pushes, pushes to the base branch, --no-verify and merges outside the engine, because these depend on a flag or refspec that permission rules can't match.
- Deny a download piped into a shell, disk wipes, and Bash commands that touch .env files or write the journal, because only a hook sees these inside a Bash command.
- Ask the person before sudo, git reset --hard, git clean -f and rm -r outside the worktree, because each is sometimes right and a person should decide.
- Wire the guard: rail init merges the deny and ask rules and the PreToolUse guard hook into .claude/settings.json, and doctor reports when either is missing, so the guards are on from the first session.
- Add doc-lint for ## Areas at ship and in CI: every glob matches a tracked file, every directory at [map] depth is covered, and ARCHITECTURE.md stays under 150 lines, so the repo map can't drift from the tree.
- Make doc-lint check that links and headings in ARCHITECTURE.md and AGENTS.md resolve, and that a change adding or removing a top-level directory updates ARCHITECTURE.md, so the docs keep pointing at what exists.
- Start a claimed ticket from the current base branch, because a branch made at add misses work merged since, such as the ticket it comes after.
- Run every git command with core.quotePath=false, because git quotes non-ASCII paths and the engine then misread them in scope, floors, the size count and context.
- Add rail docs: pages ship inside the engine, and the config and CLI reference pages are generated from the engine, so the docs a project reads match the engine it runs.
- Add the docs pages for the loop, tickets and states, so an agent new to a project learns the railroad from rail docs.
- Add the docs pages for review, the contract, retries and consult, so the answers an agent owes the rail are written where it looks.
- Give a fresh retry budget when a person approves a ticket or an amend, as with any other continue, because a person's act resets it.
- Add the docs pages for guards, packs, ADRs, environments and working away from the desk, so a project can run Rail day to day from rail docs.
- Add the forge, which talks to GitHub only through gh api REST calls: PRs open at add (a contract PR outside auto_tiers) or at claim, take the ticket's title and description at ship, and auto tiers merge through the async merge endpoint once the required checks are green, so tickets reach main without a person.
- Derive the forge's states: a PR closed without a merge drops its ticket, a conflict or a red required check returns it to implementing with the check's output, a PR behind its base is rebased with no agent work, and a requested merge is noted in the local cache.
- Make labels the person's controls: rail:needs-you marks every wait (one saved search is the inbox) and holds a ticket when a person adds it, and rail:go approves a contract or continues any wait, with the PR's comments in the agent's next brief.
- When only CI waits remain, next returns gh run watch for the PR's run, then rail next, so nothing polls.
- Add a fake GitHub to the tests (tests/fake_gh.py), so the pull-request lifecycle is tested end to end without a network.
- Add rail intake: GitHub issues labelled rail, or any tracker with --external-id, become ticket stubs once each; the agent writes the contract and saves it with rail amend --file, and a deploy issue that starts with Commit: names the ticket that caused it.
- Add the red-base check: when verify fails at ship and on the base branch too, the attempt doesn't count, next opens one fix ticket for the base, and other ships wait for it.
- Add the notify hook (Notification, idle_prompt), which announces each new wait for a person once as a desktop notification, so an unattended desk still hears about waits.
- Add the sweep: after [sweep] after unreviewed LOW tickets and ticketless commits, next offers rail sweep, which runs the free part and one review pass over them and writes a summary the agent turns into tickets, including "make it a check" tickets; its merge carries the Sweep: trailer.
- Document GitHub setup, running from GitHub events, and the sweep, and make the loop, states, away and environments pages describe the forge.
- Add a README with install and setup, so a person new to Rail can start from the docs alone; and let doctor say when the GitHub plan offers no required checks instead of calling it a mistake.
- Fill what a newcomer working from the docs alone ran into: the init task now asks about a project's existing agent workflow and leaves its commit to the person; the launchers write no bytecode into projects; rail docs works before rail init; commands get RAIL_BASE for range scans; the briefs and docs say how to write Areas, .worktreeinclude and ticket drafts; and a merge answers with the project's root as its cwd.
- Make a ticket whose after dependency was dropped wait for a person, because it could otherwise wait forever.
- Make rail init ask the remote for its default branch when the clone has no origin/HEAD (cloud clones have none), so init run on a setup branch no longer takes that branch for the base.
- Make the guard leave another repository alone: it follows cd and git -C, judges a ticket worktree by its own branch, and lets a gh merge through when it names a different repository, so a session with several repositories can push to the others.
- Bring the failing step's output into a red check's brief when the check run comes from GitHub Actions, whose check runs carry no output of their own: the engine reads the job's log.
- Add allow rules for the agent's own verbs (rail next, advance, add, answer, amend, status, context, docs, doctor, intake, sweep, consult) and gh run watch to the seed's settings, so the loop is decided by rule before any prompt and before auto mode's classifier; the person's verbs get no allow rule, and rail answer --owner always asks. An existing project keeps its own allow rules and gains these.
- Fix three misreadings of real GitHub: a pull request merged a moment ago read as dropped, because GitHub's list of pull requests carries merged_at and no merged flag; the brief's size line counted already-merged lines when the project's own checkout was behind the base; and a setup merged with a merge commit sent its own commits to a sweep. The sweep now counts what landed on the base branch, one entry per merge.
- Close holes in the guard's handling of other repositories: a cd it can't follow (cd -, popd, a subshell, cd before ;, ||, & or |) no longer moves it to another repository; --git-dir, GIT_DIR and a push to this project's URL or folder count as this project's from anywhere; a gh merge is judged by the repository it names (-R, --repo=, GH_REPO=, a URL, the api endpoint), with {owner}/{repo} meaning the current one; and an operator stuck to a parenthesis still separates commands.
- Make rail answer --owner ask in every position and by path, and stop argparse accepting abbreviations such as --own.
- Split the guard by where it runs: in a Claude Code cloud session the rules that protect a person's own machine (asking before sudo, git reset --hard, git clean -f and rm -r outside the worktree; denying a download piped into a shell) step aside, because the VM is disposable and an ask stops an unattended run. The rules that protect the rail stay. The static ask rules for sudo, reset and clean leave the seed's settings, since the hook asks the same locally; doctor says when an older project still has them.
- Make Claude Code cloud sessions the standard setup. The engine reads where it runs (CLAUDE_CODE_REMOTE, or RAIL_CLOUD), and rail doctor says which.
- Add [commands] provision and rail provision: in a cloud session and on a CI runner Rail installs what the checks need, once per machine, and next asks for it on a machine that lacks it; on a person's own machine it installs nothing and shows the command.
- Give the init task a cloud form: the agent sets the project up and opens one pull request, and the person confirms by merging. rail init writes .rail/ruleset.json for the person to import, because a cloud session can't change repository settings, and doctor links each GitHub settings page, checks that merged branches are deleted, and prints the lines for the cloud environment's setup script.
- Take ticket IDs from one counter branch, rail/ids, moved by a plain push that only one clone can win. A cloud session can't push tags or delete branches, so a tag or a branch per ID wouldn't work or would stay for ever.
- Make a claim protect only work in flight, because each cloud run is a new session: a shipped ticket is moved through CI and its merge by whichever session looks, a wait for a person shows from every session, and work with no journal event for [claim] stale_minutes is resumed. next takes in issues labelled rail by itself and labels every wait at once, and each wait's brief says what to do on the pull request.
- Add [review] model and [consult] model, passed to the command as ANTHROPIC_MODEL and RAIL_MODEL; the model that answered is shown in the Evidence table. Record the cloud session's link in each claim and at the end of each pull request.
- Add the cloud page to rail docs, put the cloud first in the README, and bring the loop, away, guards, GitHub, runner, environments, review and tickets pages up to date.
- Make rail amend show a contract that changed before approval on its pull request, and open the contract pull request for a ticket from intake once the agent has written its contract; before, such a wait had no pull request to label.
- Remove the research folder (the plan, the spec and the study notes the framework was built from): the framework stands on its README and rail docs. Comments, tests and this changelog no longer cite it.
- Remove names left from building the framework: a status line that named a build phase, the old `resumable` key in next's answer (`held` says the same, with more), the reading of per-ID branches that only a test project ever had, and a test file named after a roadmap phase.
- Make the ruleset file name the default branch, so the one file in seed/ fits every repository and can be imported straight from the framework; the README and the docs say where it is and that GitHub wants it downloaded first.
- Say on a contract pull request that it must not be merged, because its page has a merge button and a person took it for the approval; with the ruleset GitHub refuses the merge.
- Let doctor count a ruleset that allows squash merges only on the base branch as squash only, so a repository set up from the ruleset file passes without also changing its merge buttons.
- Add tests/run.py, which runs the tests on several workers, because each test drives the real launcher through real git and the suite took four minutes on one core.
- Read GitHub once per command instead of once per derivation: what the engine read holds until it writes there, fetches, pushes or runs a shell command, and a pull request is read on its own only once its ticket has shipped. A ship went from 17 GitHub calls to 7, which is most of what a real rail call waits for.
- Remember git's answers about refs and objects until the repository changes, and keep the engine's compiled files in the home folder instead of compiling it on every call; neither leaves anything in a project.
- Add rail save and two hooks that run it, at the end of each agent turn and at most every ten minutes while the agent works: the work in flight is committed and pushed as it is, with no checks and with [skip ci], so a machine that goes away takes minutes of work with it and not a whole ticket. Where no hook runs, the brief asks the agent to run it.
- Make each save a sign of life: it writes a saved event, and advance writes one before a long command when the last is old. A quiet ticket now means a session that isn't working, so another session's work is resumed after 30 minutes with no event instead of 60 ([claim] stale_minutes, with [claim] save_minutes for the saves).
- Tell a session whose ticket was taken over to stand down: it reads the remote's journal too, so its save, its advance and its next all say the ticket moved on, and its unsaved work stays in the worktree.
- Count a pull request merged before its ticket shipped as the person's approval, not as a finished ticket: next records the acceptance, starts the branch again from the base (a branch can't be rebased over its own squash) and opens a new pull request. Any open ticket whose pull request is gone gets a new one.
- Write Rail's hooks into a cloud machine's own Claude Code settings from rail provision, which also links rail onto PATH, because Claude Code loads a repository's hooks only in a session that starts with that one repository. The hooks find the project a command runs in from above several repositories, and step aside where the repository's own hooks loaded. The environment's setup script is now three lines that call rail provision.
- Add the journal page to rail docs: the journal's files, every event and step, the stored review runs and what a reviewer returns.
- Write the sign of life before a review run reads the head it resets the worktree to; written after, it left the branch behind its own pushed commit, and no later push went through.
- Mark a drop in the counter branch too, so it outlives the ticket's branch: a dropped ticket whose contract had reached the base branch looked approved again once its branch was deleted.
- Read a command that follows a shell keyword as that command: then git push -f, { cd -; ... } and ! git push were missed, because the guard looked only at the first word.
- Hold a ticket while an engine command works in its worktree, and make saves skip a held ticket: a save hook that fired while advance was inside a review pushed the reviewer's scratch files, and the reset after the review left the branch behind that push.
- Stop rail next crashing when it runs with no session id in a clone where a Claude session has started: it read the session marker's folder as a file.
- Leave the machine's link and hooks alone when provision runs from a ticket's copy of an engine that differs from the project's own: the hooks call the project's engine, and one that doesn't know them would fail on every tool call.
- Stop the guard reading variables from its own environment when it follows a command: `cd OTHER && cd "$OLDPWD" && git push origin main` was allowed when the hook inherited an OLDPWD outside the project. It follows only ~, $HOME and $PWD now.
- Make the guard read the command that runs: one behind a wrapper with its own arguments (`timeout 60 git push -f`, `xargs`, `sudo -u NAME`, `nice -n 10`, `builtin`), one given by its path (`/usr/bin/git`), and the commands handed to a shell (`bash -c "..."`, `eval ...`) were not judged at all. After a sourced file, an eval the guard can't read, or `env -C DIR`, a command is judged as this project's.
- Save deleted and renamed files: after `git rm` or `git mv` in a ticket's worktree every save failed, so the work was no longer pushed and the ticket looked abandoned. A rename now counts as both of its names.
- Tell the agent when a save fails in a hook: the pulse hook passes the error on, where it used to go to a log nobody reads.
- Count a merged contract as the owner's approval only when the ticket's own pull request was merged: a ticket file that reached the base branch inside another ticket's merge was read as approved, with no person involved.
- Fail the scope check when a ticket's branch changes another ticket's file: only its own ticket file is outside scope_paths.
- Stop a URL in a merge message from passing for the repository a gh command names: `gh pr merge 5 --body "see github.com/other/repo"` was allowed. Also read `gh pr -R OWNER/NAME merge`, a full api.github.com endpoint, and an exported GIT_DIR.
- Make the guard read command lines as the shell does: a newline inside quotes ends no line and a here-document's body is data, so a commit message or pull request body that mentions `git push -f` is no longer denied; a line continued with a backslash, a here-document fed to a shell, `$(...)` and backticks are now judged.
- Leave files whose names say they hold secrets (.env, *.pem, *.key, SSH keys) out of saves, and say so: a save is pushed before verify and its secret scan run.
- Keep the save hook's ten-minute stamp in the session's own file under the home folder: in a session whose project folder is a ticket's worktree the stamp was never found, so the hook fetched and saved after every tool call.
- Follow an exported GH_REPO in the guard: `export GH_REPO=OWNER/NAME && gh pr merge 5` is judged by the repository it names.
- Let the session that reads a person's answer go on with the ticket: after a rail:go or an accept on a ticket that waited for a person, the run that recorded it left the ticket to the session that had claimed it, and with the label gone nothing resumed it for 30 minutes or more. A person's answer also no longer counts as a sign that the claiming session is alive.
- List a ticket another session holds under held in next's answer also when a rail:go that answers no wait is on it.
- Stop the guard judging every later push as this project's after a push from another repository to a local folder that is a repository: two flags shared one name.
- Teach the guard's line reader shell comments, $'...' quoting, process substitution and arithmetic shifts: an apostrophe or <<EOF in a comment, or a shift written like a here-document, hid the lines after it from the guard.
- Read GH_REPO= only as an assignment in front of a gh command, and believe an exported GH_REPO or GIT_DIR only when it points at this project: in an option's value, or exported and then unset, it made a merge of this project's pull request pass as another repository's.
- Stop following a cd the shell may skip or run in a child: `true || cd OTHER && git push origin main` runs the push here.
- Stop a # inside a word from hiding the rest of the line from the guard: `curl https://x/y#frag && git push origin HEAD:main` passed.
- Read changed file names from git exactly (status -z) and commit only what a save really records: a name with a double quote or an arrow in it made every save fail, and a file staged and then deleted made one fail.
- Judge every line of a command as a command again, whatever quotes, here-documents or comment signs surround it: telling text from commands let a command run unjudged wherever the guard and the shell read a line differently (an escaped $', a shift in $[...], a partly quoted here-document word, a here-document handed to a shell through a wrapper). A message line that starts with a denied command is denied, and the answer says how to pass the message. A test now runs each denied command in real bash, in every place a line can put one, and checks that what bash runs was denied.
