## 1. What it really is

A small Python CLI, 2,331 lines at `main` (`statem/core.py` 1,733, `cli.py` 376, `miniyaml.py` 212), no dependencies, at version 0.1.0. It holds a YAML graph, a JSON pointer per run, and runs checks on `goto`. The engine is real and simple. The value is not in `main`: the unmerged `[v4p90]` branch adds about 70,000 lines and holds the authors' lab notebook, which is the best thing in this repo for us. The paper is also there, removed from `main` (`git show b9476a0:docs/statem-paper.pdf`).
README claims the code does not support (all VERIFIED):
- "Blocks invalid transitions: Yes". Only if the agent chooses to call `goto`. Nothing stops edits, and `state.json` is a plain file. `design.md:16` admits it is not a hard harness.
- "spec hashes... to detect or deliberately rebind edited runbooks". `spec_hash` is written (`core.py:234,262`) and never compared on `main`. `[v4p90]` added the check later.
- "A transition is a transaction" (README). The paper itself says "checked, logged, and recoverable, rather than fully transactional". `out_hook` effects survive a failed edge hook (`core.py:392-408`).
- The 92.1% / 95.28% results cannot be reproduced from the repo. Only one family of the evaluated profile is public (`examples/terminal-bench-2.1-git-webserver-deploy-family.md`: "broad selector, gate catalog ... absent"). The README table has no baseline. Paper footnote 3: 83.1% is "a model-matched public reference rather than a newly rerun, agent-version-matched A/B control". 95.28% falls to 93.26% if the nine trajectories flagged for possible reward hacking score zero; the authors agree four should not count. The paper also says the results are runtime plus a benchmark-adapted profile, with no component ablation.

## 3. Challenges

- **Ceremony as a default.** The strongest result here. The team grew to a 791-line runbook and 37-file manifest, then reset to 86 lines and 10 files. On one known-positive task: $11.61 and 48m to $1.03 and 12m42s, same raw reward (`...v4p62-thin-family-routing-design.md`). They warn platform and version differed, and it is one task. BusinessBench adds negative transfer: RefactorBench -2.78 under a too-heavy profile, and Attendance got no workflow at all. **Verdict: they are right that controls must be admitted by evidence, not assumed.** Every AF lane step should have to justify itself the same way. INFERRED for coding work; their tasks are not PR-sized repo tickets.
- **Independent reviewer at MEDIUM.** v4p62: "bounded inline review can produce valid decisions, while the heavy path materially increased cost". But the role-authority doc still requires an independent accept for promotion. **Verdict: unsettled, and AF's Mode A is the worst option:** costs a subagent, proves nothing. Make it provably independent or label it self-attested, then measure.
- **Enforcement posture.** StateM has no guards and reached strong scores, which suggests much failure is drift, not malice. Yet nine of 445 trajectories were flagged for possible reward hacking in a cooperative harness. **Verdict: AF is right to keep hard stops on irreversible and evidence-forging moves.** The paper agrees YAML editability "does not provide this security boundary". I did not see the flagged trajectories, so I cannot say what gaming looked like.
- **Bash plus files.** Python stdlib gives JSON, typed errors and unit tests in about 2,300 lines. AF already requires python3 and jq on top of bash. **Verdict: StateM is right; a rewrite would remove awk YAML and string JSON.** Files as runtime stays right.
- **Stored pointer vs derived state.** StateM stores `current`. AF derives state from git each time (`compute_next`, `gate.sh:321`), so "changed after ship" is detected. StateM cannot notice code changing after verify passes except through bespoke receipts. **Verdict: AF is right. Do not adopt a pointer.**
- **Graph in YAML vs decision table.** The paper's point is that the control layer must be cheap to modify. True for experimenting, but an agent-editable graph is the weakness. **Verdict: keep table logic in code, move lane policy (which steps per tier) to data so lanes can be tested and trimmed.**
- **Human accepts every ticket.** StateM has no such step. **Verdict: AF's premise is too strong as a default for orchestrated use.** Make it policy, with the unaccepted outcome being a non-mergeable class.
- **Review limited to changed lines.** Family gates check the whole consumer path, which is not in the diff; the v4p58 regression came from evidence narrower than the claim. **Verdict: StateM is right.** Filter findings by required evidence, not location.
- **18 skills and long AGENTS.md.** State-local prompts load guidance when relevant; family practice is deliberately hidden until `self_review` (yaml:44-48). **Verdict: StateM is right.** `next` should carry the small relevant text.
- **Copy-in.** Tool installed once, project holds only a runbook and ignored state. **Verdict: StateM is right.** It removes the template history, `scripts/` collision and upgrade gaps.
- **Selftest as main proof.** See Take row 1. **Verdict: it proves mechanism only.**
- **Tickets as the unit.** StateM has none: no scope, branch or claim. It is single-agent. **Verdict: keep tickets;** StateM offers no alternative for parallel repo work.

## 4. Delete or simplify

- **Mandatory lessons on every MEDIUM ship** (`gate.sh:299`, `lessons_ok`) and much of `memory-lint.sh` (317 lines). The paper: "More remembered procedure is not better memory", and "experience must be filtered before it becomes memory". Its DNA and video cases show failure feedback stored as false rules. Make lessons optional, promoted through evidence, with removal as a normal action.
- **Resume machinery.** `statem prompt` and `compact-prompt` exist because a pointer needs rebinding. AF derives state, so `gate.sh next` already resumes. Do not add them. `agentic-handoff` can probably shrink.
- **Awk YAML config.** Replace with a parser plus strict keys, deleting dead keys.
- **Skills without a state that invokes them.** Audit which ones `next` ever names. INFERRED candidates: `agentic-idea`, `agentic-api`.
- **Anything unmeasured after the eval exists.** Adopt the rule: non-regression is safety evidence, not value (`...20260825-tb3-control-scope-ledger-v1.md`).

## 5. Orchestration

- Explicit addressing: `--run-id`, `--state-dir`, `--agent-id`, `--json` on all commands, plus env equivalents (`cli.py:58-69`). AF relies on cwd and branch. Add `--json` and `AGENTIC_STATE_DIR`. For several clones, put stamps and reservations in git refs; a directory only helps worktrees on one host.
- Host glue stays thin. The adapter writes task and deadline, starts the run, injects `cur`, installs one Stop hook, collects artifacts, and fails the trial if the final state is wrong (`statem_codex_git_webserver_deploy.py:414-438,510-516`). That last check is outside the agent's turn, a useful model: **the orchestrator re-runs the gate after the agent exits.**
- `[v4p90]` line on authority: an intelligent orchestrator "may recommend" routing, but "only a content-addressed gate may authorize and apply it". AF should adopt this: orchestrators call the gate, never replace it.
- Standalone use: the Stop hook works for Claude Code and Codex with the same `decision: block` shape. AF needs a non-zero default and a budget per step, not per run.
- `[v4p90]` `statem/team.py` (1,760 lines) has claim, submit, reduce for fan-out; the paper explicitly leaves multi-agent as future work. Not studied in depth; not a proven design.

## 6. Do not copy

All VERIFIED in code unless marked.
- **`--yes` passes every `manual` and `checklist` at once** (`core.py:727,740`). In a non-TTY it is required, so natural-language gates are no-ops. `confirmation: none` in the benchmark YAML is read by nothing; it appears only in the strict key list (`core.py:76-77`).
- **`llm_review` with no command falls back to manual, and `--yes` then passes it** (`core.py:784-789`). A missing reviewer silently becomes self-approval, our Mode A problem again. The `origin/codex/windows-compat-issue-2` `design.md` says `--yes` does not bypass `llm_review`; the same fallback is still there (`core.py:809` on that branch).
- **Agent-written dynamic checks can set `on_failure: continue`.** Validation checks type and reason only (`core.py:1516-1524`), and `_has_blocking_failure` honours it (`core.py:1628`). A failing check then passes.
- **Budgets are reset by cycles.** `max_attempts` is per entry, so `repair -> check -> repair` gets a fresh budget. No shipped runbook sets it (grep: 0 in all three examples).
- **No locking.** `_write_state` is atomic but read-modify-write is unguarded; `history` lives inside the same file, is not append-only, and has no hash chain. `start SPEC --run-id` silently rebinds to any spec (`core.py:261-262`).
- **No default command timeout** (`core.py:757-765`). AF's `command_timeout_secs` is better. All checks in a `goto` run even after one fails (`core.py:369-373`).
- **Relative paths resolve from the spec's directory** (`core.py:1652-1666`), a surprise in repo use. Terminal states are matched by name via env var (`statem_stop_hook.py:21`), not spec.
- **`main` Stop hook gives one nudge.** It allows on `stop_hook_active` (`:26`). `[v4p90]` removed that. The README's "till-finish" is INFERRED to overstate `main`.
- **Forgeable markers.** `source: "statem_fixed_family_gate"` and `source` starting with "agent" are plain strings (`family.py:179,345`). The selection check depends on `task.txt` in a `chmod 777` dir (`statem_codex...py:154`); INFERRED an agent could replace it.
- **Gates with side effects.** `run_git_webserver_check` pushes real commits, leaves the target file on the branch, and edits `authorized_keys` (`family.py:476-505,555-588`). It may complete the task's final step while "checking" it. Never let a verifier change the deliverable. The trial uses `--dangerously-bypass-hook-trust`.
- **Benchmark-shaped families.** Regex families were written around a named task (`configure-git-webserver`). Their own guide warns against post-hoc practice, and the paper discloses the DNA and video cases. Do not cite these scores as evidence for AF.
- **Overbuilding in `[v4p90]`.** A 204 KB promotion gate, dozens of `v4pNN` runbooks, then a reset. They said so themselves. The nested runbook feature went in dormant.
- Suspicious content: none. No prompt injection found. `_remove_session_logs` (`statem_codex...py:440`) deletes raw sessions after conversion; a design note explains this as a publication constraint, but it reduces auditability. `/Users/qinziheng/...` path remains in `examples/hooks/README.md`.

## 7. If you rebuilt the framework

Keep derived state, tickets, claims, narrow hard stops and the `next` command. Rewrite as a stdlib Python tool installed once, with `.agentic/` holding only project data. The contract is whatever the claim commit says, recomputed and never trusted from the working copy; checks can only be added. Every outcome is typed JSON with distinct "moved", "blocked", "needs human" and "budget exhausted" results. Default lanes are thin, and each extra step carries an evidence class and must pass a matched comparison with a frozen build before it stays on. Unattended runs always end in a truthful class, and only `release_candidate` can merge.
