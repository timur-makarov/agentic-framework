Head `c472fa4`. MIT (`LICENSE`, © Michael Kaiser). The repo is missing from `other-solutions/MANIFEST.tsv`, so the license comes from the file itself. Paths are relative to the repo. `fw:` means the framework.

## 1. What it really is

An outer-loop runner: `runners/generic/run-loop.sh` (686 lines; twin `run-loop.ps1`, 715) starts a fresh headless agent CLI per attempt, re-runs one project gate script, starts a separate verifier CLI, parses `VERDICT: PASS|FAIL`, feeds failures back into the task block, and escalates after 3 attempts. State is a markdown backlog (`loop/tasks/todo.md`) plus gitignored `loop/state/`. VERIFIED.
Real size is about 3,500 lines; 1,310 of them are the HTML report and its two generators. One author, 34 commits (July to September 2026), 12 co-authored by an AI model. No stars or adoption data in the repo. VERIFIED.
Maturity: careful and young. The git log shows repeated audit passes. There is no CI (`.github` holds only templates). The only E2E is a Windows-only mock (`demo/`). The changelog records one real-agent run (0.1.2), which at once exposed a blocker the mock could not catch. VERIFIED.
Claims that overreach: "The runner trusts no one" and "Only the runner writes the attempt counter" (holes in section 6); "roughly 2× tokens ... near-zero attention cost" is unmeasured, and token tracking is an explicit non-goal (`docs/superpowers/specs/2026-07-02-agent-loop-toolkit-design.md:153`); the README's re-open diff claim is false (D2).

## 3. Challenges

- **Agent drives the script (framework) vs script drives the agent (repo).** Repo is right for unattended and orchestrated runs; the framework is right interactively. An agent that is told to run a command can skip it, and in Mode A it holds the reviewer too. Verdict: support both over one state machine. Keep `next` and `advance`; add `run`.
- **Hooks as the main guard.** The repo has none except Stop, and its boundary is a post-hoc diff. Verdict: the repo's direction is right for evidence-forging moves, which hooks cannot reliably stop anyway. Keep a thin hook set for what cannot be undone (remote pipe to shell, force-push, secret reads). Move protected-path checks to the diff audit. Hooks still matter: the repo has no secret or network protection at all (section 6).
- **Three lanes.** Repo has one lane: gates, then verifier, with a global off switch. `[critical]` is unused by the runner (README). Verdict: one lane is too blunt for cost, but this suggests LOW/MEDIUM could merge if the verifier is cheap and script-run. The real difference left is HIGH's human merge. Decide with data; nobody here has any. ASSUMED that two lanes suffice.
- **Review limited to changed lines, with findings and declines.** Repo reviews the whole task diff against acceptance criteria, gives one binary verdict, and the author cannot decline: FAIL means retry, three strikes means human. The framework forbids a verdict outright (`fw:gate.sh:924-927`). Verdict: the repo's verdict plus no-decline is the better unattended shape. It removes "author declines with no reason". But "when in doubt, FAIL" with no bound can burn three attempts on nits. Take: blocking findings must tie to an acceptance criterion or a defect the diff caused, callers included. Do not bind to added lines; that is what drops real defects.
- **Human accepts every ticket.** In the repo, the human writes tasks and turns the loop on; that one act authorizes the batch. Verdict: the framework should allow batch acceptance, such as an orchestrator or human authorizing a set. The per-ticket gate also blocks all writes in the checkout. But repo authorization is unprotected too: new agent-written headers are never checked (`:565-576` iterates only the before-list), so a worker can add a task the runner will then pick up. VERIFIED. Enforce by comparing with a trusted commit.
- **Copy-in distribution.** Repo also copies but with an installer into one directory. Verdict: partial win; see section 2.
- **Bash and files as runtime.** The repo shows the price: JSON parsed line-by-line with a "cmd must be first key" rule (`:55-69`), `ID=VAL` strings as maps (`:169-171`), and a second full PowerShell implementation. Most of `tasks/lessons.md` is encoding, path and quoting traps. Files plus git as state: right, both agree. Verdict: keep files and git; write any new outer runner in python3, which the framework already requires. ASSUMED that this reduces defects; evidence is only the repo's bug history.
- **In-memory run state vs derived state.** The repo needs `in-flight.txt` recovery (`:377-390`) because it holds state in the process. `fw:compute_next` derives from files, so it needs no resume path. Framework is right.
- **Long AGENTS.md and 18 skills.** The repo's agent instructions are 40-line `PROMPT.md` and 50-line `VERIFIER.md`, per role. With the runner owning sequence, role prompts suffice. That supports cutting prose in unattended mode. One real-agent run is weak evidence. INFERRED
- **Selftest as main proof.** The repo's changelog is the best argument against it: "the mock ... never passes through Claude Code's permission layer", and every real task would have escalated (`CHANGELOG.md:74`). Verdict: the framework needs at least one real-agent smoke run per supported CLI. Lesson also applies to its 210 mechanical checks. `tasks/lessons.md:52-55` adds a good rule: run each new check once against a deliberately broken state.

## 4. Delete or simplify

- `report_sha_ok`'s no-record pass: delete the branch (`fw:gate.sh:239`).
- Mode A as the default reviewer: drop it, or keep it only for interactive use, labelled unattested.
- `F1: declined` in unattended mode: human escalation replaces it, as in the repo.
- Protected-path regex in hooks: shrink once the diff audit exists in `advance` and CI.
- `/agentic-status` as the status path: a JSON status output could replace much of it. Keep skills for judgment only.
- The test ratchet in gitignored state: delete or redo; the repo's lesson is that anything in local state vanishes for CI.
- `tracker`, `exception_max_days`, `models.*`: dead; delete or wire.

## 5. Orchestration

- **As an orchestrator:** the repo is a minimal one, serial, for one repo. Its generic contract is good: a command template, a prompt file, a timeout, a stdout log. Worker and verifier CLIs stay swappable. `--manual` runs the same pipeline with a human pasting prompts, for IDE-only tools.
- **Inside an orchestrator:** weak. No `--json`, German-only output, no lock (documented at `tasks/todo.md:62-65`; a second runner hijacks the first's attempt), `exit 0` hides escalations, no branch isolation. The closest thing to a data contract is the JSON block embedded in `report.html`.
- **For the framework:** a stable contract needs `gate.sh next --json`, `run --max-attempts N`, exit codes for at-rest / human-needed / agent-work / step-failed / infra-failed / escalated, a lock per worktree, and shared claims outside local state. Retry state belongs to the orchestrator when one exists, so `run` must be optional and `advance` stay a single step.
- **Standalone:** the on/off flag shows a nice default: no effect on normal work (`loop.enabled`, `stop-gate.sh:26`). Use it only for the stop-hook nag. A guard that an agent can disable by deleting a gitignored file is no guard.

## 6. Do not copy

Defects below are VERIFIED by reading, not run, unless marked.

- **D1. Escalated work stays on the working branch.** No reset, no branch (`:655-668`); no `worktree` or `checkout -b` in the runner. The next task builds on unverified code. `VERIFIER.md` even says leftovers "must not be held against it". If leftovers keep gates red, later tasks fail too (INFERRED). Framework's `ticket/NN` branch is the right design. `done.md` means "task verified", never "HEAD verified".
- **D2. Re-opened tasks hide earlier attempts.** Escalation deletes the diff base (`:667`, ps1 `:683`), so a re-open takes current HEAD as base (`:497-498`). The verifier never sees earlier attempts' code. The README says the diff "always covers the task's own attempts since its first one".
- **D3. The trust boundary covers only `loop/`.** The pathspec at `:546` leaves `.claude/settings.json`, `AGENTS.md`, `CLAUDE.md`, the test files and CI config writable. The verifier runs in that same tree with that agent config (`:628`), so a worker can steer it (INFERRED; the verifier may also catch it in the diff). Own-task acceptance text and `lessons.md` are writable too (`:565-576` checks only other tasks' headers), and the verifier reads both. Run the verifier in a detached worktree with base-branch agent config. The framework's Mode B has the worktree but still uses HEAD's config.
- **D4. Same-uid means all of this is advisory.** State files are not read back mid-run, but they are read at next start (`:411-420`), so a worker can edit `attempts.json` or `task-base.txt` for the next run. `git update-index --skip-worktree loop/gates.sh` would hide a gate edit from the diff (INFERRED, not run). A `setsid` background process could write `verdict.md` after `:617` (INFERRED). The default preset grants unrestricted `Bash` with no sandbox.
- **D5. Verifier CLI outage is charged as a worker failure.** The exit code at `:628` is ignored. No verdict means FAIL, the worker reruns, and the attempt budget burns.
- **D6. Exit 0 with everything escalated** (`:686`).
- **D7. Blockers are not a path.** `PROMPT.md` rule 10 says set status open and write `**Blocker:**`. The runner never looks for it (grep: the word occurs only inside the error text at `:585`), so it counts as a failure and retries twice with the same missing information. The framework's `blocked-on-answers` is better. The fix is a distinct human-needed state.
- **D8. Scope is prose.** No script enforces `**Scope:**` (grep finds no check). Worker runs `git add -A`. Framework's frozen scope is better. Same for ordering: "topmost open", no `blocked_by`, no tiers.
- **D9. Empty gates exit 0.** The placeholder only warns (`:446-448`). Verified tasks can have no test evidence. No floor guard either: a worker can weaken project tests while `gates.sh` stays untouched. Keep `fw:floor-guard.sh`.
- **D10. No persisted evidence.** `verdict.md` and logs are gitignored and overwritten per task. After a run only a `done.md` line remains, and that file is agent-writable. The runner's final writes are also left uncommitted (no commit after `:645`). `last-verified-sha` is written and never used by the bash runner's logic, and it is advanced on escalation (`:658`), which contradicts its name.
- **D11. Overbuilding.** Dual PowerShell and Bash implementations, parity tests, encoding work, a live-reloading 830-line HTML page, German-parsed keywords required even with English prompts. Take the idea of one JSON status; skip the page. Do not add a Windows port.
- **D12. Commit-it-all retry state in the backlog.** Runner mutates `todo.md`, a human-edited, line-parsed file, with awk. Raw gate output is pasted into it, then fed to the next agent, so test output becomes prompt content. Keep feedback in a separate file.
- **Suspicious content:** none found. Verifier prompts are ordinary; no hidden instructions or network calls in the files read.

## 7. If you rebuilt the framework

Keep the first-match state machine derived from files, branch-per-ticket, frozen contract, floor guard and CI re-derivation. Change the shape to two layers: a pure step function (`next`, `advance`, JSON output, clean exit classes), plus an optional outer `run` in python3 that spawns worker and reviewer from command templates, with timeouts, an attempt budget, failure feedback and escalation. Reviewers run in a detached worktree with base-branch config, and a blocking verdict cannot be declined by the author. Enforcement moves from text regex to tree diffs against a trusted commit, in `advance` and CI, with thin hooks left for irreversible moves. Ship from a clean `template/` payload into one namespaced directory. The repo's own lesson should set the bar: no feature counts as proven until a real agent CLI has run it.
