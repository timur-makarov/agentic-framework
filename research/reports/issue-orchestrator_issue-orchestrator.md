## 1. What it really is

A deterministic Python control plane that sits outside the agents. It turns labelled GitHub issues into worktrees, launches coder and reviewer CLIs in terminals, validates what they claim, pushes, opens PRs, and leaves merge to a human. It is not a template: it is a running product with a dashboard, Control Center, MCP server, VS Code extension and SQLite state.

**Size and maturity (VERIFIED):** 342,199 lines of Python in 1,335 files under `src/`, 462,486 lines under `tests/`, 3,680 commits since 2025-12-04, 37 ADR files, one main author plus agents. README calls it early beta, `0.x`. It dogfoods on itself and a second repo ("porchpin", cited in many issue notes). The incident numbers in code comments and ADRs show real operation, not a demo.

**Claims the code does not support (VERIFIED):**
- `docs/design/guardrails.md:98` and `docs/architecture/hooks.md:246,308` describe a signed `.issue-orchestrator-verified` marker that startup checks. That name, `hooks_hash`, and "invalid signature" appear nowhere in `src/`. Only docs mention it.
- `docs/design/guardrails.md:90` says completion commands set `ORCHESTRATOR_GH_AUTH`. No Python sets it; `S/infra/doctor/checks/guardrails.py:41` only removes it. The wrappers compare it to a fixed string (`S/scripts/gh:72`, `S/scripts/git:56`), so any agent can set it.
- `docs/design/guardrails.md:10` says agents hold no GitHub credentials, and ADR-0005 says HOME is isolated per worktree. The code says otherwise: `S/execution/agent_runner_env.py:8-19` calls the scrub "hygiene... not isolation", `S/execution/terminal_subprocess.py:51` sets `isolate_home=False`, and `S/entrypoints/_auth_middleware.py:57-64` says the callback token is not a boundary against same-user agents, because the admin token file is readable.
- `hooks.md` lists Layer 1 as "Not by the agent" bypassable. Hooks parse shell text, and `docs/design/guardrails.md` itself admits absolute-path execution cannot be stopped locally.
- ADR-0034 says yolo is removed system-wide. It is still Proposed, `S/domain/sandbox_scope.py:16-20` is opt-in with default off, and this repo's own config runs `permission_mode: bypassPermissions` (`.issue-orchestrator/config/modes/default/main.yaml:29`).
- "Humans always merge" (`guardrails.md:8`) holds only for the default branch. Integration mode merges approved PRs into the integration branch by itself (`S/control/integration_branch.py:10-16`).
- `docs/design/goal-pilot.md` is marked planned, and says so honestly.

The code comments are more honest than the docs. Trust the code when they differ.

## 3. Challenges

- **Bash plus files as the runtime.** ADR-0023 rejected shell + workers because edge cases grow into the Python orchestrator. The repo proves both halves: deterministic control is right, and doing it fully costs 342k lines. Verdict: FW's "scripts own state" holds. `compute_next` as a decision table is the same idea as Observe-Plan-Apply (ADR-0014). But `python3` is already required, so typed JSON, schemas and locking should move there, leaving bash as a thin entry. Do not chase this repo's coverage.
- **Tickets as the unit of work.** Here it is a GitHub issue with labels as crash-safe truth (ADR-0013). That shares state across clones, which FW cannot. The price is eventual consistency (ADR-0002) and a large family of reconcilers, stale-label handlers and drift policies under `S/control/`. Verdict: keep file tickets as the default, and make the tracker a real port with one host adapter. Do not make labels the only truth.
- **Three risk lanes.** The repo has no lanes. Every completion gets validation and review; `risk` is reviewer output, not author input (`S/domain/review_artifacts.py`). Verdict: FW's lanes save real cost and the repo has no answer to token spend per small fix. But an author-set, mutable tier is the weak part. Keep lanes, floor by path, freeze at claim, and let the reviewer raise and never lower.
- **Review limited to changed lines.** Directly contradicted: `repo-specific/prompts/reviewer.md` requires tracing through boundaries, searching similar paths, and checking both sides of contracts. `location` is optional. Verdict: the repo is right. FW's rule makes the likely defects (unchanged callers, deleted lines) invisible. Bound review by requiring evidence, not by line position.
- **A human accepting every ticket.** Contradicted. A label routes work; only agent-filed work needs approval; a human merges at the end. Verdict: repo is right. Move human time from acceptance to provenance gates and the final merge.
- **Enforcement in local hooks.** The repo keeps hooks narrow (`--no-verify`, merge, `core.hooksPath`; `S/infra/hooks/block_no_verify.py`, 800 lines) and treats local layers as defence in depth, with server-side checks as the real wall (`docs/architecture/hooks.md`). Its comments concede same-user agents can reach the admin token. Verdict: FW should state the same thing: a same-user agent cannot be fully contained by hooks or files in its own reach. Trust needs a credential the agent lacks: branch protection, plus CI that runs or verifies the reviewer. The author-forged critic gap cannot be closed locally with a hash file. Note this repo closes it structurally (the engine launches the reviewer and accepts verdicts only for an open turn), yet a same-user agent could still forge through the admin token (INFERRED from `_auth_middleware.py:57-64`).
- **One hook set for three tools.** The repo uses per-tool wiring over one packaged policy, plus Codex execpolicy rules. Same shape as FW `adapt.sh`. Its extra: `doctor`/AI-gate helpers spawn a real CLI to check the hook blocks (`S/infra/hooks/_ai_gate.py`; I read only its start). Verdict: FW's shape is fine; add a live probe.
- **Copy-in distribution.** Contradicted, and the repo is right about the split, though its full package is heavier than FW needs.
- **18 skills and a long AGENTS.md.** The repo has 22 Claude skills and a 20 KB `AGENTS.md`, so it does not argue for less. `AGENTS.md:21` admits a rule "has been ignored multiple times." Its stronger lesson: `QUALITY_GUARDRAILS.md` records a decision to stop relying on longer prompts for quality. Per-role prompts plus injected protocol (`S/resources/*.md`) carry the runtime contract. Verdict: FW's condensed AGENTS.md is better. Role prompts should carry procedure.
- **Selftest as main proof.** Contradicted: unit, simulated, live-agent, budgeted and exam lanes. ADR-0032 also shows a hollow required check (3 passed, 26 skipped), caught late. Verdict: repo is right, and FW should fail on skipped proof, not count it green.

## 4. Delete or simplify

- `critic-response.md` declines: replace with a `disagree` turn answered by the reviewer, capped by a no-progress limit.
- `bound_findings` format parsing: replace with a JSON decision and a protocol-error path. This removes the silent-drop class.
- `report_sha_ok` in Mode A (`FW: gate.sh:239`): it proves nothing. Make gate-launched review the default, or label Mode A as advisory.
- The "human sets `status: open`" step and the global write freeze for human-authored tickets.
- `FW: scripts/hooks/guard.sh` regex breadth: cut to the irreversible moves and say plainly that the boundary lives on the server.
- Test ratchet with local stamps: replace with a committed baseline.
- `tracker`, `exception_max_days`, `models.*`: wire to a port, or delete.
- Do not add a dashboard, MCP server, or terminal replay to the framework. Those belong to orchestrators.

## 5. Orchestration

- **What it shows an orchestrator needs:** a run identity for each session, a per-run capability (`X-Completion-Capability`, `S/entrypoints/completion_intake_routes.py:34`), a typed completion, idempotent submission keys (`S/domain/completion_intake.py`), outcome vocabulary, and evidence that outlives the worktree.
- **Hard-won rule:** validated work must survive abnormal termination. ADR-0035 (Proposed) cites branches stranded with 14 and 34 commits because every artifact lived inside the worktree, and teardown had no idea validated work existed. FW's state in `.agentic/state/` per worktree has the same exposure.
- **Containment:** one session's failure must stay its own. One missing run dir once aborted 902 ticks (`S/control/completion_containment.py:1-12`). FW's `next --all` should tolerate a broken ticket.
- **Plug-in shape for FW:** `next --json` returning state, actor, action, outcome and reason; `advance` with exit codes by outcome kind; `submit` taking a completion record; config dials for authority; remote refs for claims. With that, an external orchestrator replaces the human steps without forking the lifecycle.
- **Conflicts cost agents real money:** PR base churn consumed 9 of 10 rework cycles on one PR, which led to integration mode (`S/control/integration_branch.py:3-7`), where the engine merges the tip mechanically before spending an agent turn. Worth noting for any parallel mode.
- **Partial delivery** (`S/control/partial_delivery_guard.py`): `Closes #N` in any commit closes an issue on merge. Useful only if FW gets a host adapter.

## 6. Do not copy

- **Scale.** 342k lines, many one-concept modules, and a large `control/` tree. The baseline holds 778 accepted debt entries, and 35 files exceed 40 KB. Much of it handles GitHub drift that FW does not have.
- **Docs that outrun code.** Section 1 lists guarantees stated as fact that are unimplemented or stale. FW should test its claims or drop them.
- **Credential wrappers as a guard.** `S/scripts/git:56` trusts a fixed env string the caller can set. `.issue-orchestrator/allow-no-verify-dry-run`, a file in the worktree, loosens the wrapper (`S/scripts/git:44-46`).
- **`bypassPermissions` by default.** Security is opt-in here (`sandbox: false`).
- **No scope freeze.** I found no `scope_paths` equivalent (`git grep` over `S/`), so a coder may change anything, and nothing stops an agent editing the `make` target the validator runs (INFERRED: the command string is digested, the target's contents come from the agent's commit). FW's frozen scope is better. Keep it.
- **Live-agent tests outside CI** (ADR-0032) and a shared `mkdir` lock with a long brief of hand rules (`scripts/coordinator/BRIEF.md`). The brief's dated UPDATE stack shows operational rules growing faster than they are automated.
- **Line-budget ratchets** push logic into many tiny modules. The ratchet can reward moving code, not simplifying it (INFERRED from the brief's "move logic to its owner module").
- **Self-grading risk.** `a31f3d06` removed a deterministic "portfolio benchmark" as hiring fluff. A benchmark of the happy path proves little. The exam design above is the useful version.
- **Suspicious content:** none found. `AGENTS.md` and `BRIEF.md` contain instructions to agents, which I treated as data. No injection attempts seen in the files read.

## 7. If you rebuilt the framework

Keep the core sentence: agents write code, scripts own everything else, with a decision table and frozen scope. Change the trust model: stop pretending local files prove anything, and move the proof to something the agent cannot write, meaning a gate-launched reviewer with structured JSON, fresh validation in a clean checkout, and CI plus branch protection as the only real wall. Make it a small installed package with a clean split between engine and project files, with `next --json`, typed outcomes, retry budgets and remote-ref claims. Replace per-ticket acceptance with provenance gates and a per-action authority dial. Ship an exam suite with planted defects as the proof, and use blind tournaments for prompt changes. Stay about two orders of magnitude smaller than this repo by leaving the dashboards and host reconciliation to orchestrators.
