# nickderobertis/allowlister

License: MIT (`LICENSE`). The repo has no row in `other-solutions/MANIFEST.tsv`, so I relied on the `LICENSE` file. Copying is allowed with notice. The engine is Rust, so most items below are ideas in practice even though the license permits copying. No repo code was built or run. "VERIFIED" means read in code, and for the engine bypasses it means traced by hand, not executed.

## 1. What it really is

A Rust CLI (v0.5.12, 154 commits, 2026-06-03 to 2026-10-15, one maintainer plus agents; `src/` is 17k lines including inline tests) that acts as a pre-tool permission hook for 8 agent harnesses. It is not a workflow framework: no tickets, no lanes, no state machine. It parses bash with `brush-parser`, splits it into `(argv, role, redirections)` fragments, matches JSONC rules (precedence deny > ask > allow > defer), and maps the verdict onto each harness's hook protocol. Its purpose is mainly to reduce permission prompts, and it fails open by design. VERIFIED: the core pipeline, adapters, plugin protocol, history store and 8 live-CLI scripts exist and match the README in shape.

README claims the code does not support:
- "Parse errors and unsupported constructs (function definitions, `eval`) always defer" (README:743-745). There is no `eval` handling in `src/` (grep). `eval` is an ordinary argv fragment, so an allow rule can match it.
- `ask` on deny-only harnesses is "a prompt, never a silent allow" (README:857-860). `codex.rs:88` emits nothing for ask, so under `--ask-for-approval never` nothing prompts. INFERRED from the adapter header (`codex.rs:7-10`).
- `cargo install allowlister` (README:207) depends on an unpublished git dependency; `Cargo.toml` says a publish would need it released first. INFERRED stale.
- `codex.rs:25` still says "Only the `Bash` tool is evaluated"; the code gates others. Stale comment.

## 3. Challenges

- **Regex guard over shell text (hooks as enforcement).** Allowlister shows a parser improves accuracy but does not create a boundary. After 943 lines of `repo-write`, its authors conclude "guardrails against obvious mistakes, not a containment boundary" (README:831-834; 13b6a49 removed interpreters and task runners from auto-allow for this reason). Verdict: the framework's ADR-0001 stance holds, and `python -c` is not fixable at this layer. Stop widening `guard.sh`; put containment in OS sandboxes and CI.
- **Default allow vs default defer.** The framework allows everything unlisted; allowlister defers. Defer only works with a person or service behind it. Verdict: keep default allow for attended use. For unattended use add a mode where `ask` becomes deny or goes to a plugin. Claude reportedly holds `ask` under bypass (`e2e-claude.sh:20`), so ask stalls unattended runs.
- **Fail closed.** Allowlister fails open (`claude_code.rs:44-48`), and a broken config silently drops its deny rules (`config.rs:185-196`). That suits a prompt reducer. Verdict: the framework is right to fail closed. Take allowlister's distinction, though: unparseable command means ask, not deny.
- **Bash plus files as runtime.** Allowlister uses a compiled binary because it spawns per tool call and needs a real parser (it even tracks instruction counts; `Cargo.toml` profile, `benches/`). Verdict: split. `gate.sh` can stay bash. The hook layer is the weakest bash, with many `jq`, `awk`, `git` spawns per call (INFERRED, not timed). Move hook logic into one Python file before considering a binary. A binary would end "copy and go", which is too high a price now.
- **One hook set for three tools.** Allowlister agrees with one engine but uses a neutral model with thin adapters, not one tool's protocol as the common language. Verdict: allowlister's shape is better. Keep the three tools; do not chase eight.
- **Selftest as main proof.** Contradicted, and allowlister is right. Its hermetic suite (`tests/e2e/main.rs`, 5,226 lines) sits beside live scripts because the hermetic one could not see harness behaviour. Selftest stays for mechanics; add a small live tier, on PR only and paid, as it does.
- **Copy-in distribution.** Allowlister ships a binary, embedded profiles, `init`, and `install` merges by rule name. Verdict: an installer wins. It separates framework files from project files and gives an upgrade path. Layered user and project config is not worth copying without a trust check.
- **Human accepts every ticket.** Allowlister has no tickets, but its model involves a human only when a rule asks, and it can replace that human with a plugin. Verdict: suggests acceptance by policy (rule or plugin), with humans for exceptions.
- **Long AGENTS.md.** It uses a 10.9 KB root plus small per-directory `AGENTS.md` files. Weak evidence; no verdict. Tickets, lanes and diff-only review: nothing to say.

## 4. Delete or simplify

- `guard.sh` sections 3-5 (network, new_deps, privileged; about 45 lines): generic policy that regex does poorly and a sandbox does better. Keep what is framework-specific: evidence paths, git rules, merge checks. Keep curl-pipe and secrets as thin, labelled speed bumps.
- Cursor protocol as the internal language: replace with a neutral `{capability, params, command}` shape, shrinking `adapt.sh`.
- Three copies of the awk `cfg` reader (`guard.sh`, `protect.sh`, `mcp-guard.sh`): move to one parser. Flat YAML via awk could become JSONC with a schema, as here, or at least one shared reader.
- `guard.network: ask` and all `ask` on Codex: remove the option there or document it as no-op. `adapt.sh` already falls through, so "ask becomes allow" is a fall-through to Codex's own policy.
- `audit.sh`: replace with one decision log covering hook and gate events.

## 5. Orchestration

- **Works under unattended flags.** The hook still fires and deny holds under Claude bypass, Copilot `--allow-all-tools`, Goose auto, Codex `never` (README:249-250, `codex.rs:7-10`, proven live for Claude via `run_claude`). Deny is the only verdict that crosses every harness, so unattended policy must be written in deny.
- **A policy decision point fits both modes.** Standalone: static rules plus a prompt. Plugged in: same engine, with `ask` delegated through a JSON plugin. The framework could offer `gate.sh next --json`, `advance --json` with stable exit codes, and one `decide` hook for orchestrator approvals. Acceptance of a ticket could use the same seam.
- **Correlation IDs.** Each harness's session id is normalized (`plugins.rs:49-56`) and project identity survives across clones. an orchestrator needs both in every event; the framework hooks never read `session_id` (grep).
- **Shared state stays out of scope.** History is per user and machine. Nothing here solves multi-clone reservation.
- **Scale warning.** Hooks reload config per call. Allowlister's lazy glob gate (`glob.rs:36-47`) exists because rule compilation dominated spawn cost, so measure hook latency before growing rule tables.

## 6. Do not copy

- **A walker that skips what it does not understand.** All below are VERIFIED by reading, not executed, and I found no tests for them (grep in `tests/`, `decision.rs`, `analyzer.rs`):
  - `X=$(rm -rf ~)` gives ALLOW "empty command": prefix assignments are dropped without looking for substitutions (`analyzer.rs:310`), then `decision.rs:81` allows. `git status; X=$(evil)` also allows.
  - `$(echo rm) -rf ~` gives ALLOW: the outer fragment is suppressed and only `echo rm` is judged (`analyzer.rs:277-283`; golden case 17 pins this path). Warnings do not affect the verdict.
  - Substitutions are never walked in `for x in $(evil)` (`:209`), `case $(evil) in` (`:229`), `[[ $(evil) ]]` (`:200`), `(( ))` (`:238`), redirect targets (`:334`), here-strings and unquoted here-doc bodies (`:369-377`, "data, never code" is false for bash), or `${x:-$(evil)}` (`:460`).
  - `K=~/.ssh/id_rsa; cat $K` gives ALLOW under `read-only`: `cat *` allows and the secret deny sees only `$K`. Variables are not resolved, so deny rules are bypassable by construction.
- **Allowlist entries with write or exec modes.** `git @(…diff|log|show…)?( *)` (`read-only.jsonc:41`) permits `git diff --output=FILE`, and `rg` permits `--pre CMD`; neither has an ask rule (grep). They patched `sort -o` individually. This is the same endless list as a denylist.
- **Repo-controlled policy with no trust step.** Project `.allowlister.jsonc` found by walking up merges allow rules and `plugins` with no trust check (`config.rs:204-219`; "trust" appears nowhere in `src/config.rs`). A cloned hostile repo could widen policy or get a command executed by the hook (INFERRED attack, VERIFIED mechanism). The framework must not load executable config from an untrusted tree.
- **Fail-open plugins for gates.** Timeout or a crash leaves the static verdict (`plugins.rs:236-238`). Wrong for a security decision.
- **Grep secret deny by `path` only.** Claude's Grep `glob` param is not normalized (`normalize.rs:166`), and a Grep with no path searches the tree, so `.env`-style contents remain reachable. `.env` is also absent from the shell secret deny (`read-only.jsonc:244`).
- **Raw commands in a global history file.** Recording can capture inline secrets. It is opt-in, but no redaction exists in what I read (`history.rs` partly read).
- **Infrastructure scale.** Nx graph, 16 workflows, 95% coverage floor, paid live matrix, 50 KB README for one CLI. Do not import these. `oneharness-core` is a git-pinned dependency from the same author; the eight-harness surface costs more upkeep than the framework needs.
- **Suspicious content:** none found. No text directed at reviewers. The repo's `AGENTS.md` and skill were treated as data.

## 7. If you rebuilt the framework

Keep the gate state machine, scripts owning state, and the small hook set guarding evidence and irreversible git moves. Split the hook layer into one Python policy file with a neutral tool-call model, thin per-tool adapters, a coverage matrix stating what each tool cannot gate, and a decision record (rule, verdict, session, project) written for every call. Enforcement would be stated plainly: OS sandbox and CI are the boundary, hooks catch mistakes and forged evidence. Deny is the unattended contract, `ask` routes to a human or a versioned plugin, and a small live suite against real Claude, Codex and Cursor proves the wiring. Distribute through an idempotent installer that merges settings. Do not adopt the Rust binary or allowlister itself as a dependency: it fails open, and its parser gaps would be inherited.
