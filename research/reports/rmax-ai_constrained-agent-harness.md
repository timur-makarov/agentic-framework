## 1. What it really is

A one-day, AI-generated research skeleton, not a working tool. All 18 `main` commits are dated 2026-06-13, driven by Codex prompts in `.hermes/codex-prompts/` and `scripts/iterate.sh`. The only later work is dependabot branches and one unmerged CI fix (`origin/fix/req-0303-dev-group-ci`, 2026-10-28). About 7,600 lines of Python in `src/`, one benchmark, Gemini-only live adapter.

The controller loop (`controller/controller.py:322-695`) is real and is driven by test harnesses with a scripted agent. As a product it does not function:
- `cah run` is a stub that prints "not yet implemented" (`cli/app.py:102-104`). So are `resume`, `cancel` and `validate-goal` (`cli/app.py:77,114,124`). VERIFIED. README, docs and Makefile all present `cah run` as the entry point, with a `--goal` flag that does not exist and a `manifest.yaml` that does not exist (real file: `benchmark_manifest.yaml`).
- Hidden verification is not wired. `hidden_checks` and `reveal_failures_to_agent` are read by no code (grep; the only use is `hidden_checks: None` in `cli/experiment.py:100`). The hidden tests in `benchmarks/payment_webhook/protected_tests/` are never run by anything. VERIFIED.
- `DockerSandbox` is never instantiated (grep). Every run path uses `FakeSandbox`, and the evaluator is a host subprocess (`cli/experiment.py:51,199`). VERIFIED.
- Approval gates, BRANCH, FAILED: `AWAITING_APPROVAL` and `BRANCH` are never entered; `ControllerState.FAILED` appears only in the tables. VERIFIED.
- The live adapter can never finish a run: it forces `completion_claimed=False` (`agents/google_adk.py:131-132`), but COMPLETE requires that flag (`controller/transition_policy.py:29`). A Gemini run can only end in budget CANCELLED. VERIFIED by reading; never run.
- `benchmarks/payment_webhook/goal.yaml` cannot load as a `GoalContract`: no `model`, `experiment` or `max_model_calls`, plus forbidden extra keys, and `allowed_commands` is the wrong type (`domain/contracts.py:124-196`, `extra="forbid"`). `tests/unit/test_benchmark.py` only does `yaml.safe_load`. VERIFIED.
- `cah experiment run` and `scripts/run_smoke_test.py` copy a non-git tree (`cli/experiment.py:179,193`; `scripts/run_smoke_test.py:31,47`) into a store that demands `.git` (`repository/git_store.py:133`). INFERRED: both crash. Tests pass because their fixture runs `git init`. The "E2E smoke" script runs no agent at all (`scripts/end_to_end_smoke.sh`).

## 3. Challenges

| Premise | What the repo does | Verdict |
|---|---|---|
| Agent has tools, hooks police them | Agent has no tools, only a proposal schema | **Repo is half right.** Outcome checks should carry trust. But one-shot JSON proposals throw away what makes Claude Code or Codex useful: reading files at will, running tests, iterating. The harness must then guess context with a heuristic repo map (`context/repository_map.py`). Keep real agent CLIs as workers and move the trust boundary to the diff |
| Bash plus files as runtime | Python 3.13, Pydantic, SQLAlchemy, Alembic, Typer, Docker | **Framework is right for a template, at this size.** Typed models here did not prevent any of the wiring bugs in section 1. The dependency stack and an SQLite event store are heavy for what they do. Typed contracts do help orchestrators: publish a JSON schema instead of changing language. `gate.sh` at 1,242 lines is still a fair argument for a small compiled or Python core; this repo adds no evidence either way |
| Tickets as unit of work | Unit is a run: goal contract plus immutable attempts | **Keep tickets**, they hold intent across sessions; there is no planning layer here. Borrow a run ID per attempt so one ticket can have many attempts, which orchestrators need |
| Three risk lanes | One pipeline, tiered evaluators, change-class gates | **Unproven, but a useful challenge.** Evaluator tiers (`evaluators/pipeline.py:11-17`) order checks by cost, unlike lanes which change ceremony. Lanes stay; change-class gates should drive human involvement |
| Review limited to changed lines | No LLM reviewer at all; only deterministic evaluators | **Framework is right to have a reviewer.** Nothing here can catch a check that tests the wrong thing. This repo is itself the evidence: green lint, mypy and unit tests shipped a stub `run` command and a false README. It says nothing on the changed-lines limit |
| Human accepts every ticket | Goal is taken as given; humans only at gates, which are unwired | **Repo's direction is right.** See "approval by change class" |
| Copy-in distribution | Installed package; `--repo PATH` targets a project, runtime in `.cah/` (`cli/app.py:84-89`, `repository/git_store.py:16-18`) | **Repo's shape is right, though `run` is a stub.** Harness outside the target repo avoids `scripts/` collisions and template-history leaks, and gives an upgrade path. Keep only config and tickets in the project |
| 18 skills, long AGENTS.md | 71-line AGENTS.md, no skills | **No evidence.** It has no human workflow to compare. Its system prompt is 16 lines (`agents/prompts.py:7-22`), which fits proposal-only agents only |
| One hook set for three tools | Avoids hooks with its own loop, one adapter protocol (`agents/protocol.py:133-140`) | **Avoids the problem by supporting one model.** An adapter that shells out to any agent CLI would make hook parity less critical |
| Selftest as main proof | Same weakness, worse: all e2e runs use scripted agents and CI skips `tests/end_to_end` (`.github/workflows/ci.yml:51`) | **Framework is ahead.** Both prove mechanics only. The benchmark idea is the fix; here it is unused |

## 4. Delete or simplify

- **Dead config, by rule.** This repo shows the end state of unread config: `branching_factor`, `context_strategy`, `checkpoint_strategy` and `failure_conditions` are parsed and ignored, and `success_conditions` is only checked for non-emptiness. The framework should delete `tracker`, `limits.exception_max_days` and unapplied `models.*`, then add a lint that fails on any config key no script reads.
- **Shrink regex hooks once the diff gate is authoritative.** Keep guards for irreversible moves only (`fw:README.md:82` list). Do not extend pattern lists to chase `python -c`; substring lists fail here the same way (`policy/commands.py:24-27`, `allowed_commands` matches basename only, so `python` allows anything).
- **Do not add a hash chain.** It would add machinery with no gain over git commit hashes plus CI.
- I found nothing here justifying removal of the critic, tiers or skills.

## 5. Orchestration

- **Standalone:** nothing usable. `cah run` is a stub.
- **As a library** the seam is good: constructor-injected `Sandbox`, `RepositoryStore`, `CodingAgent`, `ControllerEventStore` protocols (`controller.py:277-292`). The lesson for the framework: name the ports (agent runner, sandbox, store, reviewer) even in bash, as config-selected commands.
- **Isolation per run:** clone source into `runs/<id>/workspace`, refuse dirty sources (`git_store.py:27-44,136-141`). Good for orchestrators with separate clones, and run IDs are UUIDs, so no shared number registry. Note the workspace never returns to the source: there is no merge or PR output. A framework plug-in must end in a branch, which it already does.
- **Machine interface is missing here too:** no `--json` on `run`, no resume (stub), cached snapshots in memory (`controller.py:124-126`). State on crash stays ACTIVE because only `BudgetExceededError` is caught (`controller.py:683`). VERIFIED. Framework needs: JSON output, exit codes that separate failure from work, a terminal failed state, a resumable state derived from git rather than a local DB.

## 6. Do not copy

- **Declared-intent policy.** `check_proposal` validates `write_files`, but `_apply_edits` applies `edits`, and `_normalized_proposal` only fills `write_files` when empty (`policy/engine.py:63`, `controller.py:812-853`). VERIFIED by reading: declare `src/a.py`, edit `tests/x.py`, policy passes. No test covers the mismatch. A `patch` edit can also touch any path in its diff, never checked against `edit.path`. `fw:gate.sh:644-655` already does this correctly on real diffs, so the framework is ahead here.
- **No post-execution check.** `protected_file_changes` and `dependency_changes` are never set by anything (grep). The dependency policy reads model-supplied `proposal.diff` (`policy/engine.py:109`), which the prompt tells the model to leave empty (`agents/prompts.py:49`). The README's "enforcement" is therefore mostly advisory.
- **The state table caught its own controller.** After failed completion verification the loop `continue`s (`controller.py:584-597`) into `_transition(BUILDING_CONTEXT, ACCEPT)`, but `VERIFYING_COMPLETION -> BUILDING_CONTEXT` permits only RETRY or REJECT (`state_machine.py:205-208`). INFERRED: `InvalidTransitionError`, uncaught, run stuck ACTIVE. The test hides it: `max_iterations=1` makes the budget error fire first (`tests/end_to_end/test_scripted_run.py:197-201`). Lesson: test the table against every real path.
- **Search that cannot search.** Any candidate that is not fully acceptable is rejected and reset to `best_state` (`controller.py:664-674`). Partial progress is discarded, so each iteration must fix everything at once. `is_better_than` is used only for stagnation. README's "bounded search" is not what runs. `BRANCH` does not exist.
- **Agent gets no failure text.** `pipeline.evaluate` returns only the vector, dropping stdout (`evaluators/pipeline.py:39-42`), and `_stagnation_report` passes `evaluation_results: []` (`controller.py:906`). The model sees `visible_tests_failed=1` and nothing else; output is not stored as evidence either.
- **Broken headline metric.** `COMPLETION_DECLARED` fires only after verification (`controller.py:620`), so `false_completion` (`reporting/metrics.py:41`) is always false. `token_usage` and `estimated_cost` are hardcoded 0 (`metrics.py:56-57`), `record_model_call(0, 0)` (`controller.py:413`), `sandbox_seconds` 0.0 (`:1016`). A dashboard of confident zeros is worse than none.
- **Hash chain as trust theatre.** Unsigned, unanchored, stored beside the data (`domain/events.py:66-79`, `artifacts/manifest.py:96-124`); whoever can write the store can regenerate it. It would not fix the framework's self-written critic. What fixes that is who runs the reviewer: a CI step, a signature, or a record the agent cannot write. `hash_chain()` is unused and `store()` overwrites with `write_bytes` (`artifacts/store.py:26`), so "append-only" is unsupported.
- **Sandbox design flaws, even if wired.** `_build_volumes` raises if a protected path is outside the workspace (`docker.py:141`), yet the benchmark's hidden dir is `../protected_tests`. Inside the workspace it would be readable, so "never visible to the agent" fails with `cat` allowed. The workspace including `.git` is mounted rw (`docker.py:135-138`) while the host runs `git commit` there (`git_store.py:53-54`). INFERRED: a planted `.git/hooks/pre-commit` runs on the host.
- **Hidden tests each iteration** (`controller.py:530`) would make them an oracle, with counts always exposed by `failure_summary.py:28`. Run them only at the completion gate, on a clean checkout, so agent-written `conftest.py` cannot interfere.
- **Green-only automation.** `iterate.sh:128-146` commits, opens a PR and auto-merges on ruff, mypy and pytest alone. Its prompt forbids "placeholder methods containing only pass", and `run` duly prints "not yet implemented". `ci.yml` installs `--no-dev` while tests live in the `dev` extra (`pyproject.toml:33`), so INFERRED: CI likely could not run them, which the unmerged fix branch supports. Useful evidence for the framework's premise that done needs an independent check of the stated goal.
- **Suspicious content:** none. Prompts and AGENTS.md are ordinary build instructions. `iterate.sh` calls a personal script under `$HOME/.hermes/`; not relevant to us.

## 7. If you rebuilt the framework

Keep: scripts own state, one command names the next move, tickets in git, real agent CLIs as workers, an independent reviewer, the diff gate. Change the shape in three ways this repo points to. Move the trust boundary from hooks on shell text to validation of the final diff against a contract frozen in the claim commit, run by something the agent cannot edit. Install the harness as a tool with a small project footprint, and expose a typed decision (`--json`, named outcomes, budget, terminal failure) so it runs alone or under an orchestrator. Add a benchmark suite with held-back checks so the ceremony has to earn its cost. Take the vocabulary and contract idea, not the code.
