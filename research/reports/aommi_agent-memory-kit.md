# aommi/agent-memory-kit: study report

Repo paths are relative to `other-solutions/aommi_agent-memory-kit/` (HEAD 84dcdff). `FW:` means the framework. The `LICENSE` file is MIT, so copying is allowed with the notice kept. The repo has no row in `other-solutions/MANIFEST.tsv` (VERIFIED by grep), so the license comes from `LICENSE` alone. Nothing was executed. Claims are VERIFIED unless labelled otherwise.

## 1. What it really is

A small Python generator that writes per-tool instruction files pointing at shared markdown memory (`memory/semantic.md`, `working.md`, `candidates.md`, `candidates.rejected.md`, `DECISIONS.md`). About 2,590 lines of Python, 1,210 lines of tests (99 test functions), 42 commits on main by one author, 2026-04-22 to 2026-05-10, plus two unmerged branches (last 2026-07-27). No CI on main.

**It is a prompt renderer. No script reads or checks memory content.** The promotion pipeline, approval modes and line caps exist only as prose in generated files. It is younger and much lighter than the framework, and its memory checking is weaker than `FW:scripts/memory-lint.sh`.

README claims the code does not support:
- **The Claude Code output shown in the README does not exist.** README:51-66 shows a Memory Discipline block with the promotion rules in `CLAUDE.md`. `adapters/claude_code.py:18-25` does not import `build_memory_discipline`, and its template (`:28-49`) never mentions candidates. The other adapters do use it. Antigravity also omits candidates (no grep hit in its adapter or templates). So the flagship, "hooks enforced" tool has no promotion pipeline. `adapters/utils.py:166-167` says adding a file to the registry is the only edit needed for all adapters, which is false for these two.
- **"Promotion requires a written reason" (README:15) is unenforced.** `Why accepted` appears only in prompt strings (`generate.py:242`, `adapters/utils.py:263`). In `auto` mode, the `init` default (`generate.py:213-216`), the agent writes its own rationale.
- **Line caps are dead config.** `semantic_max_lines` and `working_max_lines` appear only where `init` writes them (`generate.py:203-204`). No script reads them. Only the Antigravity workflow text mentions 300 lines.
- **The "eval loop" has no producer.** Nothing writes `captures.jsonl`; only `eval/replay.py` and its test mention it. `_hash_memory` has no CLI, so `memory_hash` cannot be produced by the tool. `replay` takes hand-typed buckets. `classify_tool` is called only by tests.
- **"Hooks enforced" (README:82) is wrong.** The Stop hook only echoes and exits 0 (`claude_code.py:133-139`). INFERRED, not tested: on Claude Code plain Stop stdout does not reach the model. `FW:scripts/hooks/adapt.sh` Stop branch needs `{decision:"block"}` for that. Tests only run a bash syntax check on the script (`tests/test_capture.py:54`).
- **Six non-hook adapters say a hook exists:** "The preprompt hook handles reading `memory/working.md`" (`codex.py:35`, `cursor.py:43`, `gemini_cli.py:30`, `hermes.py:38`, `openclaw.py:35`, `windsurf.py:30`). Only Claude Code has that hook, so `working.md` loading silently fails there. The fix (`origin/agent/fix-working-memory-hook`, d97f572) covers two adapters and is not merged.
- **The upgrade path does not upgrade.** README:139-140 runs `generate.py all`, but `should_generate` skips any agent already in state (`generate.py:374-378`). Only `--force` regenerates. Approval-mode config changes hit the same skip.
- **Smaller.** `docs/planning/vision.md` (README:149) is gitignored (`.gitignore`), so the "graveyard" link is dead. "5 prompts" (README:28) is 14 (`generate.py:143-188`). PyYAML is imported (`generate.py:69`) but no dependency file exists. "No version drift" (README:131) has no version number behind it. README drops the HIGH-to-LOW confidence ratings (8b3dc21), and OpenClaw stays listed after its section was removed as "not verified" (f93ac93).

## 3. Challenges

- **Prose can hold process rules (kit) vs scripts own state (framework). Framework is right, and this repo is the evidence.** The kit's central feature never reached its main tool, and 99 tests stayed green because they assert on `build_memory_discipline` output, not on what each tool receives. Prose has no failure signal. The author reached the same view: "A prose closeout rule helps, but CI is the enforcement" (branch `DECISIONS.md`).
- **A written reason is a gate (kit README:15). Wrong, for the same reason as the framework's self-written critic report.** Text the same agent writes proves presence, not independent judgment. The kit's rationale and `FW:report_sha_ok` passing with no record are one defect. Do not treat `Why accepted` as evidence. The human gate is the PR diff, or the entry is advisory.
- **One hook set for three tools (framework) vs per-tool adapters (kit). Split the verdict.** Behavior belongs in one place, so the framework is right: seven hand-kept templates produced the false hook sentence six times. Tool configuration, however, is better generated than hand-maintained, so the kit is right there. Also, "8 agents" is 1 tool with hooks plus 7 instruction files. `codex.py:108` says Codex has no hooks, while the framework wires `.codex/hooks.json`. Breadth without verification rots quickly; three tested tools beat eight claimed.
- **Copy-in distribution. Both use it, and the kit is half right.** Vendoring keeps the "no install, no runtime" benefit and works offline. The real defect in the framework is the missing split, not the copying. Keep copy-in as the base, with one folder and a scripted upgrade. Do not adopt "ask your agent to update" (README:133), which is an unverified prose upgrade.
- **Tickets as the unit of memory. Framework is right; the kit's session scratchpad is the wrong unit.** `working.md` is gitignored, so it is lost in a fresh clone, which is exactly the framework's "local state" gap. One file per ticket merges cleanly (`FW:memory-lint.sh:8-10`). The kit's shared `candidates.md` will conflict across parallel branches (INFERRED).
- **Selftest as main proof. Both share the flaw.** Generate-then-check is a good mechanical property, but neither repo tests what an agent actually sees. A cheap fix applies to both: snapshot the full rendered context per tool and assert required content is present.
- **Staging before durable memory. Mostly already covered.** The framework's lesson line, TTL and needle staleness (`FW:memory-lint.sh:145-172`, `:265-307`) beat `candidates.md` on verifiability. Do not add a staging tier. Add only the recurrence signal and reasons from section 2.
- **Long AGENTS.md. Agreed, no change.** 1e4bc57 cut generated `CLAUDE.md` from 537 to 46 lines by referencing rather than inlining. Framework AGENTS.md is 88 lines and already follows this.

## 4. Delete or simplify

- **Mandatory `Lessons: none` files.** `FW:gate.sh:299`, `:503`, `:1127` block MEDIUM/HIGH ship until the file exists. With only one optional grep reading lessons, this is ceremony (INFERRED). Either build the read path from section 2 or drop the requirement.
- **`env-lint.sh` wiring checks** could shrink if tool configs become generated. Keep the checks generation cannot cover, such as the Cursor failClosed and Codex network ones.
- **The CONTEXT.md header claim** ("read by every planning and implementation pass") should be made true or removed.
- **Do not add a memory subsystem.** No `working.md`, no approval modes, no separate semantic and candidates files. The kit's main lesson for the framework is that its write side is already sufficient and its read side is missing.

## 5. Orchestration

- **Hooks are not a delivery guarantee.** The kit's memory arrives by tool hook or instruction, and most tools have neither reliably. An orchestrator should pull context explicitly, for example `gate.sh context NN --json` returning capped CONTEXT, relevant lessons and scope. That also works as the session-start payload.
- **`--check` is a clean machine contract:** read-only, exit 0 or 1, diffs on stdout (`generate.py:450-513`). It is the shape `gate.sh next` needs, compared with its overloaded exit 1. Keep "drift" and "failed" distinct, though; the kit does not need to and the framework does.
- **Non-interactive setup matters.** `init` uses `input()` only, so `scripts/quickstart.sh:17-32` pipes 14 positional answers through a heredoc. One new prompt silently shifts every answer. The framework's installer must take flags or a config file.
- **The kit's ethos rules out orchestration.** "Single-user, local" (README:16), gitignored `working.md` and `.last_checked_commit` all fail on separate clones. Anything needed across clones belongs in git or refs.
- **Standalone value is real but narrow.** Tool-neutral files in git are a sound base, and the framework already has them.

## 6. Do not copy

- **The Claude Code settings merge.** `claude_code.py:262-271` swallows invalid JSON and rewrites the file from `{}`, and `.update()` replaces any existing `UserPromptSubmit` and `Stop` hooks. This contradicts "custom content is preserved" (README:80). A host's guard hooks could be silently removed.
- **Skip-if-generated re-run safety.** `generate.py:374-378` plus `.generated_state.json` causes the upgrade bug. Regeneration should be idempotent and always run. That state file is also not gitignored in host projects (`generate.py:292-293`), so timestamps churn.
- **`eval/replay.py` as a measure.** `plan_stability` compares only the first bucket (`:172-176`), of one run, with no quality signal. `_hash_memory` includes gitignored, constantly edited `working.md` (`:135`), so `memory_delta` is nearly always "changed". The fallback checks `search` before `web` (`:74-83`), so an unknown `WebSearch` becomes a filesystem read, and `ls` matches any name containing those letters. It should stay out of any claim of measured value.
- **Per-turn reminders.** `preprompt.txt` is 15 lines on every prompt and asks for one extra read each turn. The Stop hook repeats on every response with a dirty tree. Neither has a dedup or a cost measurement.
- **`curl | bash` quickstart** (`scripts/quickstart.sh:3`). `FW:guard.sh` rightly denies this pattern. It also clones a nested `.git` into the host repo (INFERRED: the host then tracks it as an embedded repo).
- **Vendoring the whole repo.** README:27 copies the 800 KB icon, landing pages and tests into each project, despite the update step's narrower list.
- **Launch-driven honesty loss.** Confidence ratings were written from testing, then removed from the README. Keep the framework's habit of admitting bypasses.
- **Suspicious content:** none found. Prompt files are ordinary memory instructions, treated as data.

## 7. If you rebuilt the framework

Keep scripts owning state, hooks as guards, per-ticket journal files and `memory-lint`'s cited, expiring memory, because this repo shows what prose-only process turns into. Change the shape in three ways: one vendored kit folder with a VERSION and scripted upgrade, separate from project-owned config and memory seeded empty at init; generated tool configs and managed AGENTS.md sections from one table, with `--check` in CI, proven on a fixture rather than the template itself; and a first-class read path, one `gate.sh context` command that gives a session or orchestrator capped memory for its scope. Most of this repo's memory taxonomy can be left out.
