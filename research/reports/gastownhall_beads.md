## 1. What it really is

- A Go CLI issue tracker for agents (`bd`, v1.3.4), backed by Dolt. It is a work-state store, not a process framework. It has no lanes, no review, no evidence model and no guard hooks (VERIFIED). Our framework overlaps with it only on tickets, claims, dependencies and session priming.
- It is the most mature repo in this study by volume, and the heaviest: 474,866 lines of non-test Go, 803,097 lines of tests, 11,542 commits since 2025-10-11, still active today (VERIFIED). About 4,700 commits are Steve Yegge's. Authors such as `beads/refinery` and `beads/crew/emma` show that orchestrated agents commit here (VERIFIED).
- The core works as read: atomic claim with compare-and-set, derived ready frontier, leases, typed exit codes, conformance suite (VERIFIED by reading; not run).
- README claims the code does not support (VERIFIED unless marked):
  - Charter: "small enough to remain reliable" and "should not know about orchestration layers" (`engdocs/PROJECT_CHARTER.md:8,31`). Reality: 119 CLI reference pages, 60 non-test `*_proxied_*.go` command twins, and 106 non-test Go files that name Gas Town, Gas City or polecats. `doctor_orchestrator_guard.go` detects `mayor/town.json`. `close_guard.go:74` says "Both pin spellings are load-bearing": Gas Town pins by status, Gas City by the column.
  - `bd human` says "70+ commands"; `docs/cli-reference/` has 119 files.
  - "Zero Conflict" hash IDs: collisions retry with a nonce, but only against the local database. Its own table gives 7% at 500 issues with 4-char IDs (`engdocs/COLLISION_MATH.md`). Cross-clone collision is reduced, not zero (INFERRED).
  - `plugins/beads/skills/beads/SKILL.md` says `version: "0.60.0"`, while the binary is 1.3.4 (`cmd/bd/version.go:19`). `PROPOSAL-pluggable-storage-backends.md` says SQLite is supported and links `docs/architecture/storage-backends.md`, a file that does not exist. SQLite was removed on 2026-07-18 (`6fd9dbda7`).
  - `docs/reference/json-schema.md:72-77` contradicts itself: the version increments when "fields are added", and additive changes "do NOT bump".

## 3. Challenges

- **Bash plus files as the runtime.** Beads is the best natural experiment here. It began with JSONL in git (Oct 2025), then added SQLite, a daemon, `deletions.jsonl`, tombstones, resurrection logic and a sync branch (`f73651a2b`). One cleanup deleted 497 beads after a resurrection bug (`7b6370f3f`). It moved to Dolt in Jan 2026 (`1dc36098a`), reverted a premature cut in Feb (`e8edba13e`, "premature dolt-test-woho transition"), and removed SQLite in July (`6fd9dbda7`). Verdict: both are right at different scales. Files in git fail as a shared coordination store across clones. A versioned SQL engine costs far more than our problem is worth. Middle path: keep markdown as the content, and put only claims and reservations in git refs on origin. Beads itself keeps data in `refs/dolt/data`, outside code branches, which also frees it from branch protection (`docs/reference/protected-branches.md`). That supports the ref namespace idea (INFERRED).
- **Tickets as the unit of work.** Agrees on the unit, disagrees on weight. A bead can be a title; `bd lint` wants only Acceptance Criteria for most types (`cmd/bd/lint.go`), and that is advisory by default (`validation.on-close: none`, `docs/reference/configuration.md:126`). Verdict: the framework is right to demand a runnable Done Contract, and beads is right that most other template sections should not be mandatory.
- **Three risk lanes.** Beads has priority and type only, and says nothing on quality. No contradiction, no evidence against lanes. Its own contributor rule is "a human reviews and stands behind every issue and PR" (`AGENTS.md`). Keep lanes.
- **Review limited to changed lines.** Beads has no review. The `release-gates/*.md` files record an external process: a separate review bead with a verdict bound to a commit, `spec_findings` mapped to each exit-contract item, `uncovered_criteria`, and tests re-run by a third role (`release-gates/be-pp7e-gate.md:7,32-42`). Verdict: this supports binding review to acceptance criteria and a SHA, not to added lines. The enforcing code is not in this repo, so this is a record of practice only.
- **A human accepting every ticket.** Contradicted. Agents create and claim freely; human input is a typed gate on one item. Verdict: beads is right for the default shape, wrong on enforcement. `bd gate resolve` "is equivalent to `bd close`" with no human check (`gate.go:766`), so its human gate has the same hole as ours.
- **Copy-in distribution.** Contradicted. Beads is right. The cost shows too: `README.md` upgrade steps across remote-backed clones are a multi-step dance, because the state has a schema.
- **18 skills.** Beads has one skill (110 lines) plus resources, and its ADR cut the skill from 3,306 to about 500 words by pointing to generated output. Verdict: right for procedure. Since `next` already prints the step, skills that restate commands should go. Judgment skills stay. Its skill version drift shows that even this needs a lint.
- **A long AGENTS.md.** Half agrees. The advice is "pointer plus generated context", yet the "minimal" block is 53 lines, and the full prime is about 1-2k tokens by its own claim (`prime.go:95`, not measured). Keep the pointer idea, not the size.
- **One hook set for three tools.** Beads has per-tool adapters over one payload. That is the same shape as `adapt.sh`, and it shows tools differ by event (`bd codex-hook`, `cursor_hook.go`). Keep the adapter. Beads' hooks only inject context; they never deny. Double-fire handling (GH#3192 in `setup/claude.go`) shows this surface is costly.
- **Hooks as enforcement.** Beads relies entirely on prose: "🚨 SESSION CLOSE PROTOCOL 🚨", "Do NOT use TodoWrite" (`prime.go`). Whether that works is unmeasured. Verdict: this is not evidence against guards. The evidence-forging guards remain justified. The regex shell guard's value stays unproven.
- **A selftest as the main proof.** Beads has conformance contracts per role (`backend/conformance/`), goldens, Oracle A, and an exploratory log that found 70+ bugs in one day of scenario sessions (`tests/regression/DISCOVERY.md`). Still I found nothing that evaluates agent outcomes; `BENCHMARKS.md` is storage speed. Verdict: both projects share the same blind spot. Scenario-driven discovery beat assertion-writing there, so add a scenario list.

## 4. Delete or simplify

- **`models.*`, `tracker`, `exception_max_days`.** Under the charter test, model choice is orchestration policy. Delete all three.
- **Global write freeze for `blocked-on-answers`.** Replace with a per-ticket hold. Unrelated work should not stop.
- **`refs/agentic/nn` reservation loop** (`gate.sh:771-777`). A short content hash (`internal/idgen/hash.go:55`) removes reservation entirely and works across clones. Cost: every `NN` pattern changes. Do it only together with orchestration support; otherwise push the ref to origin.
- **Skills that restate commands** (likely `agentic-route`, `agentic-status`, parts of `agentic-task`, `agentic-implement`; INFERRED, skill bodies not read). Replace with `gate.sh prime` output.
- **`agentic-handoff` as a document flow.** Beads keeps resumable notes on the work item. A notes section in the ticket plus `next` should cover it (INFERRED).
- **`stop_followups: 0`.** A default that does nothing should either be on or be removed.
- **Mandatory ticket-full sections.** Keep Done Contract, scope and risk. Move the rest to optional, with lint only where a tier needs it.

## 5. Orchestration

- Beads is the clearest example here of being both: a person uses `ready / claim / close`, and Gas Town or Gas City drive the same store. What makes that work: `--json`, a typed conflict on claim (`issueops.ClaimConflictError`), `ready --claim`, leases, CAS flags, opaque string assignees with no agent registry (`docs/multi-agent/coordination.md`), `prime.disabled`, a cursor journal, and metadata as the extension field.
- The framework needs the same list, in this order: JSON output with a closed exit table, `ready --json`, atomic claim on origin, `--if-head`, per-ticket holds, then an `autonomy` policy that an orchestrator sets (for example auto-accept up to a tier). Unattended mode is then a config value, not a new code path.
- Keep orchestration concepts out of the framework's core. Beads wrote the rule and still leaked: `merge-slot` help says "polecats" and "rig" (`merge_slot.go:21-25`), `hooked` is a built-in status, and `ready --mol-type` takes `swarm` and `patrol`. Adding a thing for one orchestrator is hard to undo once its users depend on it.
- Beads does not own the agent's work, branch or merge. The framework does. That is the framework's real value when plugged in, and it should stay: evidence, scope, review. Issue tracking itself could be delegated to a tracker such as beads through a small port, but only if the framework still owns the contract fields.

## 6. Do not copy

- **Dolt and the route matrix.** Embedded, server, proxied, http and federated modes mean most commands exist twice. `.bazelrc` is 32 KB. This is the opposite of a small template. VERIFIED.
- **Self-asserted identity.** Actor is `--actor` > `BEADS_ACTOR` > `git user.name` > `$USER` (`cmd/bd/actor_test.go:12`). Re-claim by the same actor returns success (`claim.go:159`). So two agents under one git identity both "win" a claim (INFERRED from code; not run), and `coordination.md` does not mention setting `BEADS_ACTOR`. The assignee close fence (`close_guard.go:64-80`) is only as strong as that string, and `--force` bypasses it.
- **Leases with no wiring.** `heartbeat` and `reclaim` appear in neither `prime.go`, `SKILL.md`, nor the agent templates (VERIFIED by grep). A supervisor running default `bd reclaim` could take work from a live interactive agent about 15 minutes after its claim (INFERRED: 5m TTL plus 2× grace).
- **Close before verify.** Prime's checklist is "1. bd close, 2. run quality gates" (`prime.go:924,938`). Close records no evidence and needs none. The framework's order is right.
- **Regex over free text for state** (`non_completing_close.go:40`). Its long comment lists the false positives. Use an enum.
- **Two JSON shapes.** `BD_JSON_ENVELOPE` has been opt-in with the envelope promised for v2.0. Ship one shape from day one.
- **Metaphor vocabulary.** Molecule, wisp, pour, bond, burn, squash, polecat, rig, mayor. It costs every reader, and `bd human` exists because the surface outgrew people.
- **Repo clutter.** A 1 MB `CHANGELOG.md`, 31 `release-gates/*.md` files, and root-level `PROPOSAL-*.md`. This is the project-history leak the owner wants removed. `info.go` also carries release notes in code.
- **Opt-out telemetry.** Usage metrics are on by default, keyed to a machine id, sent to `gastownhall-eventsapi.com` (`internal/metrics/metrics.go:21,51-75`, `docs/reference/faq.md:49-64`). The README does not mention it (VERIFIED by grep). Do not add this. Note it if anyone proposes installing `bd`, and set `DO_NOT_TRACK=1`.
- **`curl | bash` as the first README install line.** The framework's own guard denies this pattern.
- **Suspicious content:** no prompt injection found in the files I read. `AGENTS.md`, `CLAUDE.md` and skills are ordinary project instructions, treated as data.

## 7. If you rebuilt the framework

Keep the core idea: one command gives the next legal move, scripts own state, a contract with runnable checks, frozen scope, evidence bound to a SHA, and guards against evidence forgery. Reshape it into three parts on the beads model. First, a small state engine with a stable JSON API and exit table, installed as a tool, with one namespace in the project and managed blocks in `AGENTS.md`. Ticket content stays in markdown; claims and holds live in git refs on origin, so separate clones see them with compare-and-set. Second, a policy table that reads config: lanes, autonomy, per-ticket waits. An orchestrator can override it, and it owns nothing about models or scheduling. Third, thin per-tool adapters that inject generated context and run the few real guards. Do not adopt a database, a graph tool or beads' surface. Use Oracle A's method to prove the rewrite matches the old `gate.sh`.
