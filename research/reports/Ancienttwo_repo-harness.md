# Ancienttwo/repo-harness

Paths without a prefix are in the cloned repo. `FW:` paths are in the framework. License: root `LICENSE` is MIT (VERIFIED), so code may be copied with attribution. The repo has no row in `other-solutions/MANIFEST.tsv` (grep found none), so the license claim rests on `LICENSE` and `package.json` only. Almost all code is TypeScript on Bun, so most items below are practical as ideas even where copying is allowed.

## 1. What it really is

- A very large, fast-moving, single-owner TypeScript CLI on Bun (npm 0.26.5). 3,625 commits from 2026-03-19 to 2026-11-06, 2,282 files, about 126k lines of TS outside tests, about 117k lines of tests. 699 commit subjects start with `fix`. Mostly agent-authored (VERIFIED by `git log`). It is real and maintained, with a very high churn rate.
- The shipped product is: a global CLI, user-level hook adapters, 10 packaged skills, GitHub issues and PRs as the task record, a merge executor, a read-only board, and a local web console. It depends on external tools: `hc` (herdr-core), CodeGraph, Waza.
- **Key README claim the code does not support:** the README diagram shows `Acceptance receipt -> Gate -> publication merge`. `publication merge` reads no receipt and no acceptance record. VERIFIED: `grep -i "acceptance\|receipt"` over `src/effects/publication/merge-executor.ts` hits only the on/off switch, and `MergeReadinessBlockerCode` (`src/core/publication/merge-readiness.ts:24`) has no acceptance code. A PASS row is read only by the board projection (`src/core/board/board.ts:290-309`). Requiring it is skill prose (`orchestrator.md` §9.1). So with `acceptance_merge: on`, a PR with green checks and no review merges. This is the framework's top gap, repeated at the last step, alongside 2,000+ lines of receipt code.
- Smaller mismatch: README says "Claude 5" routes; `ROUTES` installs 6 for Claude (`src/cli/hook/route-registry.ts:74-124`, VERIFIED by reading). "Guardrails" on Codex have no Bash route (`:99-101`, `hosts: ['claude','pi']`).

## 3. Challenges

- **Tickets in files as task state: repo disagrees; partly right.** It built plans, sprints, contracts and a task plane for months, then deleted them all (`d02a082f` #820 on 2026-10-17; `91afe2cf` #1218 and `1072bbfb` #1219 on 2026-10-30). The issue and PR now own task state; "no plan, contract, review, notes or approval artifact is mandatory" (`AGENTS.md`). VERIFIED history; the commits give no stated reason, so "ceremony cost caused it" is INFERRED. Verdict: for multi-clone orchestration the repo is right, because a shared provider solves number and claim visibility. For standalone and offline use, file tickets still work. Keep file tickets as the default and implement a real `tracker: github-issues` adapter, or delete the key. A cheaper claim path than comments: atomic `git push` of `refs/agentic/claim/NN` (INFERRED, not in this repo).
- **Human accepts every ticket: repo disagrees; repo is right.** Humans gate four effects instead: main publication, deletion, credentials or permissions, release or production (`agentic-development-flow.md:95-99`). A ticket does not need a human; a merge might. Authority is GitHub `author_association` (`src/core/board/source.ts:315`), not an agent-editable file. Verdict: replace per-ticket `status: open` with a config-driven intake policy, keep the human at merge for HIGH.
- **Hooks as the guard layer: repo disagrees; mostly right.** Over time it deleted guards down to path boundaries. Bash guard is explicitly "a literal tripwire, not a shell interpreter" (`src/cli/hook/mutation-bash.ts:1`), advisory on unparsed input. Real trust moved to branch protection, CI and the reviewer sandbox. It also says plainly that local state cannot stop a same-user process (`docs/control-bot-boundary.md`, "File ownership and link checks"). Verdict: client hooks are for mistakes, not adversaries. The framework should stop adding regexes and move evidence checks to CI. The repo goes too far: no secret-read guard at all, and no Codex Bash route.
- **Author-chosen tier: repo says "the diff sets the tier", but enforces less.** Tier is a `tier:` label set by the coordinator. The diff check is advisory board rule R3 (`src/core/board/attention.ts:289`, `src/core/board/hazards.ts`). Framework's `risk_paths` floor at ship is stronger. Verdict: keep the framework's mechanism, take the principle, and read floors from the base commit (Take 1).
- **Bash plus files as runtime: repo chose a full TS runtime.** Result: typed routes and good tests, but 126k lines and a Bun dependency. It gives no enforcement advantage at the key step (section 1). Verdict: bash is not the framework's main problem. Consider moving only JSON-heavy parts to python3, which is already required.
- **Copy-in distribution: repo uses a global CLI with an opt-in marker; split verdict.** Nothing is vendored; hooks no-op without the marker (`src/cli/hook/runtime.ts:160`); marker can pin `minimum_harness_version`. Great for many repos and upgrades. But enforcement depends on each machine's install, and CI, cloud workers and teammates need the same runtime. Verdict: keep files in the repo so a clone is self-contained; add a manifest and upgrader (Take 5).
- **Changed-lines-only review: repo agrees** (`agentic-development-flow.md:156`) but gives a home for off-diff defects. Keep the limit, add the follow-up path.
- **One hook set for three tools: repo agrees in shape** with one registry and per-host route lists, and exposes the gap honestly by host. `failClosed` per route (`route-registry.ts:88`) is cleaner than a global rule. Adopt per-event fail-closed declared in one table.
- **18 skills, long AGENTS.md: repo has 10 packaged skills.** Root `AGENTS.md` is 60 lines but 9.5 KB, with most procedure in huge references. Line count is not the measure; bytes loaded at session start are.

## 4. Delete or simplify

- **`.agentic/journal/lessons/NN.md` as a MEDIUM ship gate.** "Lessons are not task logs" (`agentic-development-flow.md:84`). Replace with a defect-triggered ledger (Take 12).
- **Hook regexes for evidence protection.** Move to CI base-SHA checks (Take 1). Keep a short deny list for destructive and secret mistakes.
- **Dead config.** The repo removes keys that have "no reader" as a recurring cleanup (`chore(policy): remove circuit_breakers, which has no reader` #1599; a manual habit, INFERRED). Add one lint: every key in `config.yml` has a reader. Drop `tracker`, `exception_max_days`, `models.*` unless wired.
- **The local test ratchet.** It skips where it matters. Either run it in CI against the base, or delete it. `floor-guard.sh` already covers removed assertions, and the repo has nothing as good there (prose rule only).
- **Possibly the MEDIUM/HIGH ceremony on small fixtures.** The repo's benchmark shows 3.3x to 4.7x tokens with no pass-rate gain on simple tasks. That is weak evidence, from another harness at a July commit, but it means the framework must prove its value.

## 5. Orchestration

- **Good model:** "The Bot decides, the harness supplies." It keeps no scheduler or budget ledger. Tools are read models and fenced commands (`board --json`, `publication merge`), with versioned `{protocol, kind}` documents. The framework should be the same: a state machine an orchestrator calls, not a scheduler.
- **Shared state lives in the provider.** Issue and PR comments with a `repo-harness <kind>` header act as a message board; "earliest claim wins, tie by comment id" (`references/board.md`); chat carries links only. It solves multi-clone visibility. Cost: a protocol of about 11 comment kinds that agents must follow by prose, parsed by regex (`src/core/board/source.ts:370`).
- **Progress is judged by side effects** (commits, pushes, check changes), never by asking a worker (`agentic-development-flow.md:166`). Copy this rule.
- **Unattended standalone:** the repo does it by `acceptance_merge: on` plus strict branch protection. Minimum for the framework: `--json`, separate exit codes, no-progress verdict, base-SHA policy, config-based intake, one integrator rule ("one merge session", `board.md`), and a merge executor with fences.
- **Batch integration** (`src/core/publication/merge-readiness.ts:107` `batchMemberMerges`): proves a batch adds no own commit, so member reviews carry over. Worth knowing; defer until parallel volume exists.

## 6. Do not copy

- **Receipt machinery without enforcement.** `acceptance-receipt.ts` (716 + 1,355 lines), merge seal, waiver grants, admissions. It stores local authority that the docs admit a same-user process can rewrite, and the merge path does not read it. For the framework's self-written critic gap, the lesson is direct: a local hash or receipt cannot prove a reviewer ran. Use something the author cannot write: a CI job that runs the reviewer with its own token and posts a status, or a required review by another account.
- **Scale and churn.** Protocol bumps with no compatibility, a CHANGELOG of 5,808 lines, plugin splits, a pixel-office board, a web console (21k lines), MCP surfaces built and deleted (#1354). Much of the code exists to manage its own migrations.
- **Hard external dependencies.** `hc` is a stated prerequisite and CodeGraph "required agent readiness"; Waza and `geju` are referenced in the contract. Review isolation is macOS only (`src/effects/review/review-isolation.ts:237`, throws on other platforms) and needs `/usr/bin/sandbox-exec`.
- **Rule accretion.** `agentic-development-flow.md:3-5` are enormous paragraphs of incident rules on worktrees. Boilerplate-heavy `policy.json` holds prose `rule` strings and leftovers like `edit_plan_gate_modes: ["off"]`.
- **Evals that do not measure what they claim.** Skill routing top-1 is 4/42 (9.5%), and the file itself says the run reflects "direct model answers, not skill discovery" (`evals/skill-routing/routing-aggregate.json`). Skill benchmark graders grep final text for tool names (`evals/benchmark.md`, 56.3%). Harness reports hard-code local paths and are stale (2026-07-22, before the plan/task removal; the `adaptive-lite` profile lives only in the benchmark script).
- **Model family table** hard-coded by prefix (`src/core/review/acceptance-receipt.ts`), and TLA+ specs (`specs/tla/`): clever but not worth it here.
- **`curl | sh` install** that also installs or upgrades Bun (`README.md`). The framework denies this pattern for agents. Eval commands use `--dangerously-bypass-approvals-and-sandbox`; acceptable only in throwaway workspaces.
- **Suspicious content:** none found in what I read: no prompt-injection text aimed at reviewers. Instruction files are normal project rules; I treated them as data.

## 7. If you rebuilt the framework

Keep the core idea: one decision table, scripts own state, the agent does what is printed, and tickets as readable files. Change the trust boundary: anything that must hold against the agent runs in CI or on the provider, with rules read from the base SHA and a reviewer identity the author cannot forge; local hooks only catch mistakes. Ship a clean `template/` with a sha256 manifest and an upgrader. Make every command emit a versioned JSON document with a closed code and an owner. Put humans on four effects (merge, deletion, credentials, release), not on ticket intake. Add a `github` tracker adapter for orchestrators. Prove value with a three-arm benchmark using seeded defects. Do not grow toward this repo's size: its best ideas are small rules, and each could fit in under 100 lines of shell.
