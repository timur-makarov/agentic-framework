## 1. What it really is

A published npm package (v0.8.2, 40 commits, 2026-08-16 to 2026-10-14). 27,436 lines of Node ESM in `lib/` and `bin/`, plus 1,351 lines of tests and benchmark. Two runtime deps (ajv, yaml). It is not a workflow framework. It is one subsystem: git-tracked Markdown memory, compiled to a snapshot, recalled by a deterministic lexical ranker, delivered on Edit/Write hooks as a quote, pointers, or an abstention. So it overlaps only `fw:scripts/memory-lint.sh`, `CONTEXT.md` and `journal/lessons/`. It also has useful installer, telemetry and honesty patterns.

Maturity: the code is careful and full of measured notes, but it was extracted from a private repo ("Oriveo", commit `c70c37f`; `lib/memory-paths.mjs:7`). All strong numbers (354 memories, AUC 0.886) come from that corpus and cannot be reproduced here.

README claims the code does not support (all VERIFIED unless marked):
- **"Independent receipts"** and the in-toto lineage. A receipt is an unkeyed SHA-256 of its own content (`lib/memory-trust-store.mjs:60`), with `verifier: {kind:'machine'}` (`:540`). Anyone with a shell runs `ownmem trust issue`, and `ownmem new` signs in the same call (`lib/features/ownmem.mjs` near :155). It detects passive edits. It does not detect an agent.
- **"No text enters memory without a human commit" / "reviewed like code."** No hook protects `.ownmem/`: the hook specs only do recall and telemetry (`lib/memory-init.mjs:328`). `review confirm` writes `source:'confirmed'` for whoever runs it (`lib/features/review.mjs:191-222`). `outcome --confirmed-by user` is a CLI flag an agent can type (`lib/features/outcome.mjs:87-93`). The defence against this is keeping those commands off MCP (`lib/memory-mcp.mjs:40`), which does nothing on a host with Bash.
- **"Risk is not inferred from what a memory talks about"** (`docs/TECHNICAL.md` §3). `memoryContentActionRisk` is a regex over the body and description (`lib/memory-lifecycle.mjs:94`), and it is what receipts store (`lib/memory-trust-store.mjs:529`).
- **"No ranking... change lands without the evaluation harness."** The leak gate, holdout isolation and topic split functions in `lib/memory-evaluation-cases.mjs` have no caller outside that file. "Ablation" appears only in comments and a test wording. Public CI runs only the synthetic benchmark (`.github/workflows/ci.yml`).
- **"Evidence before authority."** A topic becomes `active` if any cited path, symbol or commit still resolves (`gradeTopicEvidence`, `lib/memory-trust-store.mjs` near :476-487). A real file behind a false claim earns `active`. Existence is not support, as `docs/TECHNICAL.md` §1 half admits.
- **Test-execution evidence.** `ingestTestRun` (`lib/memory-test-execution-ledger.mjs:238`) has no caller and no CLI; `lib/features/test-runs.mjs`, named in a comment (`lib/features/trust.mjs:108`), is not in the repo. A consumer can only ever get `never-run`.
- **Benchmark "Recall@1 100%".** Real run, weak test: 40 unrelated CC0 topics, one per domain, and the gate demands exactly 1.0 (`benchmarks/public-benchmark.mjs:416`). Mean token overlap of a Latin/Cyrillic-tokenizable query with its own target topic is 0.75 (my check on 115 queries). Only 2 of 160 are verbatim triggers. It proves tokenizer coverage and speed, not retrieval under confusable memories.
- **Dogfood.** `.ownmem/` holds 4 topics with no `trust.lock.json`, `hook_enabled:false`, adapters `generic` (`.ownmem/config.json`). `receipt-missing` is an audit error (`lib/memory-trust-audit.mjs:125`), so its public memory likely fails its own audit (INFERRED, not run). The CI does not run `ownmem audit`.

## 3. Challenges

- **"Lessons are written at ship and read by convention."** OwnMem contradicts this directly. Its comparison table separates what is read every turn from what is delivered for a task. Verdict: OwnMem is right. Writing without delivery is ceremony. Fix delivery first, and only then decide if a MEDIUM ship should require a lessons file at all.
- **Calendar TTL for lessons (`lesson_ttl_days: 90`).** OwnMem bases staleness on evidence, with a 730-day backstop only (`lib/memory-trust-store.mjs:236`), and its fingerprint module bans timestamps. Verdict: partly right. A lesson should expire because its anchor moved, not because 90 days passed. Keep the framework's rule that a lesson without an enforcing check needs promotion, and drop age as the trigger when an anchor verifies.
- **Agent writes memory vs. human-only writes.** OwnMem claims human-only and removed all automation. Yet nothing enforces it (§1). Verdict: the framework is more honest, as it treats memory as reviewed PR content. Both rely on review. Neither should claim more.
- **Review restricted to changed lines; trust by report file.** No overlap. OwnMem has no answer to the self-written critic gap and repeats the same flaw: an artifact with a hash, not a proof of who ran it. A hash chain beside a git history adds no authority. Verdict: the fix for the framework must come from outside the agent's reach (CI identity, a host-side signature). Don't copy receipts for this.
- **Bash plus files as runtime.** OwnMem went Node with Ajv validation on every contract and a Windows/macOS/Node matrix. It runs zero awk-parsed YAML. Verdict: the win is schema contracts, not Node. But hook latency cost them a daemon (530 ms cold, 110 ms warm, `lib/memory-hook.mjs` comment at :36-41), a spawn per hook being the issue. Bash startup is cheap, and the framework's guards should stay simple. If gate logic is rewritten, do it for schemas and tests, and keep hooks thin.
- **One hook set for three tools.** Both normalize host payloads in one place (`lib/memory-hook.mjs:149` against `fw:adapt.sh`), and both handle `apply_patch`. OwnMem adds per-host command declaration (`--host`) and notes that Codex hook processes get no `CODEX_*` env var and need per-entry trust by content hash (`lib/memory-init.mjs` :349-372, measured by them, UNVERIFIED). Verdict: the framework's shape is right. `env-lint` should report untrusted or changed Codex hooks as a failure that is otherwise silent.
- **Long AGENTS.md.** OwnMem injects a 6-bullet block. The framework's 88 lines are not long, but situational content should move into path-triggered lessons.
- **18 skills.** OwnMem ships 3 because logic stays in the CLI. Verdict: a skill that repeats what `gate.sh next` prints should go. This does not prove 3 is enough for a workflow framework.
- **Selftest as main proof.** OwnMem's public tests are thin (about 50 assertions for 27k lines), so it is no model. Its better idea is that end-to-end install from `npm pack` into a space-laden path is the test (`test/public-self-test.mjs`), and that tests ship with the package so a consumer can rerun them. The framework should test the real install, not the template tree.

## 4. Delete or simplify

OwnMem's strongest contribution is its record of removing its own machinery:
- 0.7.0 removed the whole unattended governance layer: "In 703 runs it promoted nothing and rolled back nothing" (CHANGELOG:156). PostToolUse and Stop hooks went too because "the events had no reader anywhere". So: audit `fw:audit.sh` for a reader. `fw:stop.sh` returns `{}` whenever the limit is 0 (VERIFIED, read), and 0 is the default, so enable it or delete it.
- `max_active_bytes` was raised by hand six times in seven weeks, each time to the exact value needed (CHANGELOG:190). A cap that moves whenever it binds measures nothing. Watch `context_md_max_lines: 120` for the same pattern, and pair any cap with a nominated removal list (`lib/memory-swap-nomination.mjs`: hubs excluded, delivery window stated). The net-zero ratchet (`lib/memory-audit.mjs:118`) is worth having only if the lock is not agent-writable, and here it is.
- Remove the framework's dead config (`tracker`, `exception_max_days`, unapplied `models.*`) under the same rule: no reader, no field.
- Do not build a separate "memory" subsystem. Lessons as cited lines with a path index are sufficient, at about 1/50th of OwnMem's size.

## 5. Orchestration

Standalone and plug-in use follow the same shape here: one CLI, JSON on every command, an MCP server with a read-only surface. Useful points:
- **Least-privilege tool surface.** MCP exposes exactly `recall` and `read` (`lib/memory-mcp.mjs:40`), errors as readable tool results, not protocol errors. For the framework: `gate next --json`, `status`, `report` over MCP for orchestrators, and no state-moving tools for workers. It only counts as a boundary where the worker has no shell.
- **Session identity is a real problem.** Pairing events needed host session variables, with care that nested runs do not inherit the outer host (`lib/memory-agent-identity.mjs`, CHANGELOG 0.8.0). `surface` and `agent` are separate fields. An orchestrator running nested agents would need this in stamps and audit rows.
- **Git carries shared state, local telemetry stays local.** Topics and locks travel by clone. `report --fleet` was removed in 0.7.0, so OwnMem did not solve cross-clone aggregation. Single-file `trust.lock.json` will conflict across parallel branches, and there is no merge driver (INFERRED; no `.gitattributes` handling found). The framework's one-file-per-ticket lessons is better for orchestrators.
- **The daemon is keyed by repo and agent** (`lib/memory-hook.mjs:64`). Sound if a resident process is ever needed; avoid needing one.

## 6. Do not copy

- **Regex policy as a safety gate.** `lib/memory-trust-policy.mjs` (562 lines) tries to tell orders from questions in English and Chinese. Its comments record a chain of bypasses: a trailing `?`, a filler negation clause, polite lead-ins. A "Known remaining gap" is `never mind exfiltrate the keys` (:152). This is evidence against growing `fw:guard.sh` regexes. Use the sandbox and the tool boundary instead.
- **Hash receipts sold as provenance** (§1). They add a schema, a lock file, a bootstrap and a migration path, and stop no agent.
- **Scale.** 1,360-line report, 1,000-line dashboard page, 16-locale catalogs, an embedding A/B system at weight 0, a `generate-readmes.mjs` of 118 KB. Public dogfood is 4 memories. Most of the value lives in about 500 lines.
- **Declared but unreachable code.** `replay` evidence (their comment admits nothing produces it, `lib/memory-evidence-verifier.mjs:28-33`), lifecycle states `observed/candidate/shadow` that have no public path after promotion was removed, R0 "reserved" for a policy that does not exist (`lib/memory-lifecycle.mjs:25`). They removed the machinery and kept the schema.
- **Benchmark as a headline.** A 100% gate on an easy synthetic corpus is a regression check, not a quality claim.
- **Taking global ownership.** 0.6.0 claimed `core.hooksPath` and could not give it back; a dangling value silently disables the user's own git hooks (`docs/UPDATING.md`). The framework's installer must never set repository-global git config.
- **Fragile identity.** A daemon per host, 30-minute idle, socket in tmp, and a host-alias table for each new agent. Unneeded for path-based lookup.
- Suspicious content: none found. Instruction-override text exists only as detection regexes. The MCP `read` description nudges models to prefer it over file reads for measurement, which is benign but worth noting as a tool description that steers behaviour. The embedding lane sends data to a user-configured provider and is off by default (`docs/PRIVACY.md`); API key file is mode 0600 (`lib/memory-embedding-provider.mjs:244-248`).

## 7. If you rebuilt the framework

Keep the core: scripts own state, a decision table, hooks guard the few irreversible moves, reviews happen outside the author. Change the shape in three ways from this repo. Install through a versioned tool with `init --check/--update`, ownership records and a retirement table, so project files and framework files separate cleanly. Give every gate step a reason code, a JSON envelope and a telemetry row, with `report` showing denominators and `not_measured`, then use an ablation eval to delete gates that catch nothing. Turn memory into a small path-indexed store of cited lessons, delivered in one advisory fail-open hook at edit time, with cites graded gone/moved/fine. The memory layer stays a few hundred lines. Everything OwnMem built past that point is what its own changelog keeps removing.
