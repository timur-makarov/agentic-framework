# heliohq_ship (Ship, v0.3.1)

Paths without a prefix are in `other-solutions/heliohq_ship/`. `fw:` means `agentic-framework/`. License: MIT (`LICENSE`, VERIFIED). The repo has no row in `other-solutions/MANIFEST.tsv` (grep for "ship" and "helio" found none), so the license comes from its own LICENSE file only.

## 1. What it really is

A Claude Code and Codex plugin: 11 routed skills plus shared references (5,891 lines of prose), 9 shell scripts (about 1,500 lines, of which `scripts/auto-orchestrate.sh` is 894), 3 hooks, and 8 shell test suites (about 250 assertions). 207 commits from 2026-03-26 to 2026-07-04, one main author. VERIFIED.

The real product is prose procedure. Code enforces very little: `/ship:auto` is a bash `phase:verdict` table fed by a verdict the LLM supplies, plus file-exists checks. It has no CI gates, no scope guard, no provenance and no risk tiers.

It stands out at the far end of delivery (PR merge-readiness), at reviewer prompt craft, and at independent planning. Its evidence is weaker than the framework's. Nothing proves it works: the tests never run an agent, and commit `b808341` says dev behaviour "is tested in production via /ship:auto runs, not in the shell harness".

README claims the code does not support (VERIFIED by reading):
- "Makes these failure modes structurally impossible." `validate_artifacts` (`scripts/auto-orchestrate.sh:308-384`) mostly checks that files exist and are non-empty. The spec check passes on the word "should" (`:319`).
- "Evidence is hierarchical... L3 is an automatic FAIL." L1/L2/L3 appear only in the README and in one note in `skills/qa/references/api.md:41`. The QA gate accepts any `.md/.txt/.log/.png` in `qa/` (`:360`).
- "The QA evaluator can only see the spec, the diff, and the running application." The guardrail blocks only the `Read` tool on two paths (`scripts/phase-guardrail.sh:59-72`). The QA prompt itself hands over the E2E report and says "Review is also clean" (`skills/auto/prompts/qa.md.tmpl`).

## 3. Challenges

- **Human accepts every ticket.** Ship has no acceptance step. `/ship:auto` runs from raw requirement to a merge-ready PR with "no user questions", and the only mandatory human step is that it never merges. Verdict: Ship is right for orchestrators, but not as the only mode. Make acceptance a policy: auto-accept LOW and MEDIUM from a trusted queue, human for HIGH, and keep the human merge. A wrong spec in Ship burns the whole pipeline before anyone looks, so a spec approval option for HIGH stays worthwhile.
- **Review limited to changed lines.** Ship reads full changed files and direct callers, and "breaks callers" is a valid finding (`skills/review/SKILL.md:47,125-127`). Verdict: Ship is right about scope, and the framework is right about noise control. Keep the trigger on a changed line and allow the cited evidence to sit elsewhere: a finding on an unchanged caller is valid if a changed line causes it.
- **Three risk lanes vs agent routing.** Ship has no tiers. `use-ship` picks the "smallest useful" route and `scope_mode` is a regex on the first verb (`:181-189`). Verdict: the framework is right. Lanes set by paths are enforceable, and Ship's routing is a suggestion. One thing to learn: Ship's atomic skills work with no task at all (`skills/use-ship/SKILL.md`). The framework could expose ticketless verbs such as "review this diff" for adoption and plug-in use.
- **Tickets as the unit of work.** Ship's unit is a gitignored run (`.ship/tasks/<slug>/`, one active per checkout). Verdict: the framework is right, because committed tickets let CI re-derive gates. Ship leaves no durable evidence in the repo beyond the PR. Ship's advantage is a cleaner product history, so keep the committed record small.
- **State derived from evidence vs stored phase.** `compute_next` derives state. Ship stores `phase` and trusts the verdict. Verdict: the framework is clearly right. Ship's bug history shows why: dead retry cap (`4f83313`), write-only `run_state.yaml` written at 12 sites and read by nothing, P2 findings passing as success (`24fc614`).
- **Bash plus files as runtime.** Ship agrees and has the same class of bugs: `gh --jq ... || exit 1` gates that could never fire (`164179c`), the awk `&` bug below. Verdict: bash is fine for a state table, but the failures show its limit. If the engine is rebuilt, bash is not sacred.
- **Copy-in distribution.** Ship's plugin wins on cleanliness and upgrades. The catch: plugin hooks live outside the repo, and CI cannot run them unless it also fetches the engine. Verdict: split the engine from project files, and pin an engine version in `.agentic/config.yml` so CI can fetch the same version.
- **Long AGENTS.md and session context.** Ship injects a five-line routing hint and nothing else (`scripts/session-start.sh:17-24`). History shows it was cut back deliberately (`d52267f`, `26dea53`, `093c92c`). Verdict: Ship is right on hint size, while the framework's `gate.sh next` injection is more useful than a static hint. Keep the state line and trim prose.
- **18 skills.** Ship has fewer skills but 5,891 lines, against the framework's 769 lines of `SKILL.md`. It needed a 505-line "content diet" (`249ad6b`), and that kind of cleanup loses contracts (section 6, item 3). Verdict: the framework's short skills are better. Skill count matters less than size and whether a script checks the contract.
- **One hook set for three tools.** Ship dropped Cursor (`43d096b`) to keep two manifests. Hook scripts need no adapter because they speak one format. Its Codex parity is checked only as a manifest test (`tests/test-codex-plugin-manifest.sh`), so behaviour is unproven. Verdict: keep `adapt.sh`. Dropping a tool is an owner product decision, not a technical need.
- **Hooks as enforcement.** Ship built always-on policy hooks for boundaries, operations and secrets, logged the same Bash bypass the framework has (`03794b2`), rebuilt them, and deleted setup entirely by v0.2 (`a821dab`, `093c92c`). The current `AGENTS.md` calls the workflow layer opt-in. The commits give no stated reason (`093c92c` has an empty body). INFERRED: its authors decided shell-regex guarding was not worth carrying. This supports keeping hooks narrow and treating CI as the real gate.
- **LLM verifiers.** Ship made a per-phase verifier "non-negotiable" (`41e969a`), then found it was never wired and deleted it, and also removed the LLM stop verifier (`43d096b`, `4f83313`). Verdict: this supports the framework's premise that scripts verify and LLMs judge. Treat the quoted "25 min/run, zero gain" and "0/10 defects" numbers as third-party claims. They come from another project and are not in this repo.
- **Selftest as main proof.** Same weakness. Ship's `TODO.md` once planned a benchmark "to generate marketing data" (`2307993`), and `benchmark/` is gitignored; a separate `ship-eval` is mentioned (`fbd506a`) but not present. Neither project has outcome evidence.

## 4. Delete or simplify

- Do a write-only audit. Ship's useful move was asking of each state field who reads it (`4f83313`). Apply the same to `fw:.agentic/state/*` and config (`tracker`, `exception_max_days`, `models.*`).
- Make lessons optional at ship time. Ship built a `learn` skill auto-invoked after every run, then removed it (`093c92c`, no reason given) along with `.learnings/`. This is weak evidence on its own. Test it: if `journal/lessons/NN.md` and `memory-lint` cannot be shown to change agent behaviour, stop gating ship on them.
- Do not add an LLM verification step anywhere a file check or derived state can answer.
- Shrink `session-start` output to state plus wiring warnings, and keep `AGENTS.md` condensed.
- `fw:scripts/review-package.sh` needs nothing from Ship unless parallel commits per ticket appear (`--commits` mode, `scripts/review-package.sh:12-15`).

## 5. Orchestration

Ship is both a standalone tool and its own orchestrator, with the host LLM as a relay around a script. What it teaches:
- The script/relay split is sound: script emits an action, agent performs it, and `SKILL.md` stays 42 lines. For a real orchestrator the relay is replaced by code, so a generated `PROMPT_FILE` is the correct seam.
- A blocked run must stay resumable. Ship's `emit_escalate` archives the state file (`:63-77`), so `resume` then fails with "No active task". The framework's `blocked-on-*` statuses are better. Do not copy this.
- Support many tasks per clone. Ship allows one state file per checkout. `SHIP_AUTO_STATE_FILE` is an env override (`:29`), but the hooks hardcode the path (`phase-guardrail.sh:28`, `stop-gate.sh:59`), so the override silently disables them.
- Idle waits should be parked on a harness primitive rather than polled, with `waiting-external` as a named state.
- Unattended mode needs explicit rules for questions. Ship's prompts say "no user questions" and each skill has a branch for it (for example `skills/dev/SKILL.md:247-249`): record the conflict, take the spec-compliant reading, continue. The framework would need the same rule per skill.
- Session ownership in state (`resolve_session_id`, `:217-223`) is a small useful idea for detecting takeover.

## 6. Do not copy

1. **Uncapped main fix loop. VERIFIED.** `review_fix_round` is bumped only when the fix itself fails (`:687-688`). `review:findings` to fix to re-review never increments it, and `tests/test-auto-orchestrate.sh:271` asserts "stays 0". Test 17 reaches the cap only by setting it by hand (`:513`). QA and E2E loops are the same (same test file `:412`, `tests/test-e2e-phase.sh:258`). The message prints "round 1/3" forever, and commit `4f83313` claims a "real retry cap".
2. **`complete` never checks the current phase. VERIFIED.** `cmd_complete` (`:600`) compares no stored phase, so `complete handoff --verdict=success` works from any phase. Without `gh`, handoff validation is skipped (`:374`). `qa:skip` and `e2e:skip` bypass validation (`:620`), and `verdict` is whatever the LLM says.
3. **Relay contract lost in a slimming pass. VERIFIED.** The status-to-verdict map and dispatch loop existed before `093c92c`. Now `skills/auto/SKILL.md:35-36` says only "follow the `/ship:auto` dispatch loop", and grep finds no definition. Prompts still say "Skip preamble and auth gate" though the auth gate is gone. `skills/design/SKILL.md:284` names a "user-approval gate" that auto does not have.
4. **Findings detection by grep. VERIFIED.** `\bP[12][-:]` (`:631`) misses `**P1**` or `P1 —`, and matches "no P1: issues". Review output is declared freeform (`skills/review/SKILL.md:172`).
5. **Template corruption. VERIFIED by a harmless awk reproduction of the same pattern.** `gsub` with raw findings (`:284-292`) turns `a && b` into `a {{FINDINGS}}{{FINDINGS}} b`. Code in review findings gets mangled before reaching the fixer.
6. **Evidence is self-reported.** Reviewers are told not to re-run tests because the implementer's report "IS the test evidence" (`skills/dev/implementer-prompt.md`, `reviewer-prompt.md:99-104`). The framework's verify stamp is the better design. The dev ledger gate also switches off silently when the plan uses `## Step N` or lists, formats `skills/dev/SKILL.md:119` accepts (`:341-344`).
7. **Stop gate weaknesses. VERIFIED.** No bound on repeats. It tells the agent how to escape ("delete .ship/ship-auto.local.md", `stop-gate.sh:130`), and the host agent is not gated from doing so (`phase-guardrail.sh:35`). It removes a corrupt state file (`:83`).
8. **Hooks fail open and cover little. VERIFIED.** Only Read, Write and Edit are gated, and only for subagents. Bash is untouched, and no matcher covers `MultiEdit` or `NotebookEdit`. The framework's fail-closed behaviour is better.
9. **Peers run with no sandbox. VERIFIED.** `claude -p --permission-mode bypassPermissions` and Codex `approval-policy: "never"` (`skills/shared/runtime-resolution.md`, `execution-drill.md`), with "read-only" stated only in the prompt. No throwaway worktree.
10. **Parallel subagents in one checkout.** `skills/dev/SKILL.md:258-263` says git's index lock "serializes" commits. From general git knowledge, the second commit fails with a lock error rather than waiting (INFERRED, not run). Tests in one story also see another's half-done edits. Worktrees were removed in `51b52ae` with "design-only" testing.
11. **Silent global install.** In no-questions mode `skills/shared/startup.md:58-70` auto-selects `npm install -g agent-browser`.
12. **Smaller bugs. VERIFIED.** `has_branch_changes` needs `origin/HEAD` (`:206`); the tests fake it, and the review skill has a fallback the script lacks. `.ship/` is not gitignored for user repos (nothing adds it, apart from `scratch/`), so run files can land in `git add`. Skills need Codex/Claude tool names and `Monitor`, so they carry vendor churn (`TodoWrite` rot, `164179c`).

Suspicious content: none found. No obfuscation, no exfiltration, no text aimed at reviewers. The session hook's injected text is what the README says. Greps for `curl|sh`, `base64 -d`, and instruction-override phrases were clean.

## 7. If you rebuilt the framework

Keep derived state, committed tickets, tier lanes, verify stamps, CI re-derivation and short skills: Ship's history shows what stored state and prose-only contracts cost. Change three things. Package an engine (plugin or pinned release) separate from a small project folder, so no template history ships. Make the engine's interface `next --json` returning an action, a typed human reason and a prompt file, with acceptance as a policy rather than a fixed human step. Extend the lifecycle past the PR: `shipped` becomes `pr-open`, `awaiting-ci`, `merge-ready`, driven by a progress ledger and failure signatures rather than counters, with reviewer output failing closed and identity tied to a subagent record. Take Ship's reviewer prompt rules nearly as they are, and its second-spec idea for HIGH only.
