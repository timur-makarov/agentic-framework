# ReinaMacCredy/maestro

Paths without a prefix are in the cloned repo (HEAD 69ee7fc3, v0.126.0). `fw:` means `agentic-framework/`. License: MIT (LICENSE, MANIFEST.tsv). Recipes, `PRINCIPLES.md`, role profiles and parts of the review gate are themselves ported from pstack (MIT, Lauren Tan, `THIRD_PARTY.md`), so copying those files needs both notices.

## 1. What it really is

- A local CLI on Bun and SQLite: a thin kernel (1,796 lines in `src/kernel/`), about 26.6k lines of plugins, about 39k lines of tests, about 1,057 tests by grep (VERIFIED; I did not run them). Almost entirely one maintainer's dogfooding: 2,436 commits, 2,345 by her (VERIFIED). No sign of outside users.
- Two products share one tree: a coordination ledger (work, decisions, dispatch, handbacks, evidence gates, a passive graph runner) and SLP, a multi-pane agent team on the third-party Herdr multiplexer (`slp-v2.ts` alone is 5,995 lines).
- The design is cooperative. `SLP.md:32` states it is "not a shell security sandbox". Install writes only `SessionStart` and `UserPromptSubmit` hooks and removes `PreToolUse` (`src/plugins/install.ts:133,147`). Nothing stops a write (VERIFIED).
- Claims the code does not support (VERIFIED):
  - `WORKFLOW.md:436` says "the gate fails while an Act on finding is neither fixed nor justified". No `.ts` file references `review-gate`, and a finished run sets its own work item to `done` whatever the verdict says (`graph.ts:686-689`). The gate is prose.
  - `SLP.md:68-70` says a reviewer accepts only after a lesson statement. `acceptWorkAs` does not check that (`slp-v2.ts:3503`).
  - README:276 still names the explore and diagnose skills, removed in 1610d62c.
  - `scripts/shape.ts` (the 1,000-line file cap) is referenced by no test, CI step or doc; `slp-v2.ts` sits on its allowlist.
  - README:5-6 "no background service" holds only outside SLP; SLP needs a long-running runtime pane (`slp-attention.ts:871`).

## 3. Challenges

- **Bash plus files as runtime.** Maestro's SQLite gives atomic leases, FTS search and read-time liveness. But the store is git-ignored (`.gitignore`, `install.ts:80`), so CI and clones see none of it, and contract, evidence and policy all live outside review. Verdict: the framework is right that the record belongs in git. Bash is at its limit for the review pipeline, though. Move new structured logic to python3 (already a dependency), not Bun.
- **Tickets as the unit.** Maestro has quickfix (no record), Light (work item), Full (bundle), and "tier determines record depth, not test count". Close to the framework. Verdict: keep tickets; state the no-record lane explicitly.
- **Three risk lanes.** Maestro routes review by diff facts (`touchesTrustBoundary`, subsystem count) via a model classifier. Verdict: both. Keep deterministic `risk_paths` floors, which a model cannot talk down. Let a classifier only add lenses, never remove them.
- **Review limited to changed lines.** Maestro's regression lens hunts "callers, data, or flows outside the changed lines"; the structure lens has `beyondDiff`, routed to the owner and never applied. The refuter kills hypotheticals instead of a line filter. Verdict: maestro is right. Line-binding is a crude proxy for "caused by this change". Bind by causation (refuter) and keep unchanged-code findings visible as Consider.
- **A human accepts every ticket.** Maestro has no acceptance step; an explicit request authorizes its stated scope only, and a recorded quote (`grant:`) carries it across sessions. Verdict: maestro is closer. Reserve humans for product forks and irreversible steps, as `policy-auto-pr` keeps merge/tag/release with the owner. But its grants are text anyone can write; the framework must keep a merge-side check.
- **Hooks as guards.** Maestro added, then retired `PreToolUse` (d875) and relies on prompts. No evidence in the repo that dropping it was harmless (INFERRED: it was retired because delegation doctrine flipped, not because of measured safety). Verdict: the framework is right to guard irreversible and evidence-forging moves. Prefer harness-native deny and sandbox over regex where they exist.
- **One hook set for three tools.** Maestro renders per harness from one source and supports only Claude and Codex. Verdict: rendering beats translating at runtime, and dropping a tool is cheaper than half-supporting it.
- **Copy-in.** Maestro proves the split, but needs Bun, `curl | sh`, a machine-global runtime and non-reproducible versions per repo. Verdict: split framework and project files, pin a version in the repo, keep policy committed. Neither side has it right.
- **18 skills, long AGENTS.md.** Maestro has 9 skills, 44 recipes, 29 profiles and 8,100+ lines of prompt text (`wc`: recipes 3,563, skills 2,152, resources and profiles 2,420), with opaque ids such as `room d128` inside it. Its repo `AGENTS.md` is short only because the bulk moved to `~/maestro`. Verdict: the framework is leaner; keep it. `recipe show` (serve on demand, no repo copy) is a fair distribution idea.
- **Selftest as main proof.** Maestro has interface snapshots, golden scenario replays (`tests/scenario-golden.test.ts`), a read-purity sweep over every verb (`tests/read-purity.test.ts`), and a journey script in a scratch `HOME` whose feature map lists its own `GAP` rows (`.agents/skills/verify-maestro/SKILL.md`). Verdict: copy the feature-map-with-gaps. It proves mechanics too; neither repo proves outcomes.

## 4. Delete or simplify

- Replace `bound_findings` and its line-format contract with schema validation; the parser goes (see Take).
- Shrink `guard.sh` regex to the irreversible set, and move reviewer read-only to native profiles. Regex coverage beyond that is theatre under `python -c`.
- Drop the unconditional lessons step for clean tickets.
- Apply gate A3 from `CONTRIBUTING.md`: "A gate is either enforced or removed, never bypassed by a flag". It argues for removing `stop_followups: 0` (dead by default) and other dead keys, and against adding opt-out flags.
- Do not add seats. Maestro deleted its Observer seat for an event-driven, model-free runtime (9fd329bd) and retired a "consult rung" (8b63695b). Monitoring needs no model.

## 5. Orchestration

- **Standalone:** the pull loop plus `next --json` is sufficient. The driver can be any harness, because the engine never spawns.
- **Plug-in:** two MCP tools only, `maestro_find` and `maestro_run`, over the same strict dispatcher (`mcp.ts:29-46`). A small surface; better than one tool per verb, which the project had earlier (19 tools, 3646ebac, later dropped).
- **As orchestrator (SLP lessons worth keeping):** the store is truth and a pushed line is only a wake-up; pane text is never a record (the "phantom record" in `ANTI_PATTERN.md`, seen four times). Each new seat answers a READY challenge before it gets work. Each generation pins pack and profile digests, and edits mid-run refuse with `SLP_SNAPSHOT_CHANGED`. Stall detection uses pane events, no model. A reset is proven by a new harness session id (`--fresh`). Reviewer is a store fact and author cannot accept own work (`slp-v2.ts:2469-2497`).
- **Limit:** everything assumes one machine. Hub, registry and SQLite do not cross clones; the framework's `refs/agentic/nn/NN` is the better base there once pushed. Liveness by PID or TTL does not cross machines. Role proof is `HERDR_PANE_ID` (`slp-v2.ts:2299`); their own review declined to treat it as auth (`CODEBASE-REVIEW-2026-09-04.md`, Considered section).
- **Self-written critic gap:** maestro does not solve it. Role separation is real only if seats are separate processes, and agent results arrive through `graph result` from the driver with no proof of a spawn. An orchestrator holding the reviewer identity, or CI running the review, is still required.

## 6. Do not copy

- SLP and Herdr: 6k-line protocol file, a third-party multiplexer, a 374-line pack whose shared block every seat carries, nine verbs that hide dozens of rules.
- Evidence gates that accept any string: `policy-proof.ts` needs only a non-empty value, `--candidate` is "opaque" and unchecked (`work.ts:937`). `policy-witness` trusts session ids from `MAESTRO_SESSION_ID` (`sessions.ts:209`), so a process can forge a second session, and it ships disabled.
- Disable-by-agent: `plugin disable` has no guard (`plugin-manager.ts:129`) and its config is git-ignored. "An agent never enables it" is prose.
- Append-only theatre: `event_log` triggers (`log.ts:35-49`) stop only well-behaved SQL; `DROP TRIGGER` works, and there is no hash chain (INFERRED, not run).
- CI gates as greps: A1 "no daemon" misses `while (true)` runtime loops; A2 is a keyword scan.
- `policy-lifecycle.ts`: a registered plugin that does nothing, "ships dark". Same class as the framework's dead config.
- Recording every user prompt into a searchable table (`coordination.ts:178,401`) with no retention control seen. Privacy cost.
- Rebuild churn: history shows conductor, Atlas, mission, Harness-OS, Rust (2026-06), TypeScript (2026-08, v0.108), then pstack replacing the main workflow in one day (2026-10-15). Doctrine reversed too: sub-agents read-only (d135), then writing (d860). 2,436 commits have not produced a stable method, so treat any single doctrine here as a hypothesis.
- Suspicious content: none found in what I read. No injection-style text; `CLAUDE.md` and `AGENTS.md` were treated as data.

## 7. If you rebuilt the framework

Keep git as the record, the single next-move table, frozen contracts, deterministic risk floors and the small prose layer. Reshape around one idea from maestro: a passive engine whose only output is a versioned JSON envelope, listing script steps it ran and agent tasks (profile, brief, schema) the driver must spawn, so a human-run agent and an orchestrator use one interface. Review becomes lenses, a refuter per finding, and four buckets with a script reconciling every finding id. Runtime logic moves to python3; state moves to the git common dir, with hashes of contract and results committed so CI can check them. Install gets a pinned version and a framework/project split. Skip teams, panes, hubs and the doctrine library.
