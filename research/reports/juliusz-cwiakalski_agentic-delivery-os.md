# Agentic Delivery OS (ADOS): study report

Labels: VERIFIED (read in code or repo data), INFERRED, ASSUMED. Paths without a prefix are in the cloned repo. `fw:` means the framework. License: MIT, so code may be copied with the notice kept. Nothing from the repo was executed.

## 1. What it really is

A one-author OpenCode prompt pack: 24 agents and 20 commands (9,012 lines, 315 KB of prompts), plus about 6,000 lines of real bash supervisors (`deliver-ticket.sh` 2,490, `batch-deliver.sh` 1,095, `ceo-loop.sh` 877, `pm-liveness.sh` 412, `install.sh` 1,135) and large mock test harnesses. 46 commits, 2026-01 to 2026-10.

The prompts are "the product" (AGENTS.md). There is no tool hook of any kind (VERIFIED by grep: `PreToolUse` appears only in change docs about something else). The 11-phase lifecycle exists only in `pm.md` prose and in a PM-authored YAML file.

The newest and best code is the supervisor layer. Its git history is a series of production fixes. Real use is credible: 28 dogfooded change folders are in the repo, and commit 003a063 claims "4523 pm-notes ledgers" across private repos (unverifiable; 45 are copies of one ledger, so the count is not distinct tickets).

README claims the code does not support:
- "Deterministic quality gates define done". The phases and gates are agent-run prose. The README's "30 min" staleness is 10 in code (`deliver-ticket.sh:55`, README:243).
- README:247 lists three approval signals. `is_pr_approved` reads only the label (`batch-deliver.sh:445-450`). The guide documents an opt-in `DELIVER_ALLOW_LGTM_COMMENT` that no script reads (VERIFIED by grep over scripts).
- `marketplace.json` says "10-phase", the docs say 11.
- "Multi-tool" holds for prompts only. All autonomy needs `opencode` (`deliver-ticket.sh:2449`) and its session database (`pm-liveness.sh`).

## 3. Challenges

- **Bash plus files as the runtime: framework right, and ADOS is evidence for it.** ADOS began with prompts in charge. An AI babysitting a script caused "~20 CEO agent sessions to deliver a single ticket" (`delivery-modes.md:47`), and its own rule became "anything that can be scripted should be". Each recent commit moved a decision from prompt to script. Bash is showing its limit, though: 2,490 lines, an awk YAML parser that needed a bug fix (003a063), subshell-global traps noted in comments. If a supervisor is added, keep bash for hooks and write the supervisor in python3, which the framework already requires.
- **Scripts own state: framework right.** ADOS still leaves phase state in `pm-notes.yaml`: "AI-driven today, because pm-notes... not yet schema-strict enough" (`delivery-modes.md`, INV-DM-4). Retro evidence shows the cost: `@coder` broke a hard rule (GH-142 pm-notes), and the PM prompt lost a commit trigger (GH-151 F-1). `compute_next` is better than anything here.
- **Hooks as guards: framework right.** ADOS has none, so a "read-only" reviewer holds `write: true, bash: true` (`reviewer.md:9-19`), and the Claude build gives every agent Write, Bash and `mcp__*`, dropping source restrictions such as `webfetch: false` (`build-claude-plugin.sh:284-292`), and "read-only" `decision-critic` gets them too. The stated "never" rules are hopes. The framework's hooks are leaky but real.
- **A human accepts every ticket: ADOS is right that this must be optional, wrong on how far to go.** `human-input-needed` plus a label read by a script is a workable interrupt. `@ceo` is too far: it may approve all decisions, including human-only ones ("Never wait for human confirmation", `ceo.md:53`), and may waive CI (`ceo.md:330`). The author of the work approves it. Make acceptance a policy by tier: machine critic for LOW/MEDIUM, human always for HIGH.
- **Three risk lanes: framework right.** ADOS has a single heavy lane; only a recorded "trivial" override skips the DoR gate, and rigor tiers R0-R3 apply to decisions, not changes. Cost is measurable: change artifacts are 77% of GH-151 insertions (2,052 of 2,669), 62% of GH-146 (3,734 of 5,985), and about 51k lines over 28 changes (top-level files only). One test plan is 2,306 lines.
- **Review limited to changed lines: ADOS is right that this loses defects.** Scope should be acceptance criteria plus changed behavior. But ADOS does not bind findings to anything and no script checks them. Keep the binding for blocking and report the rest instead of dropping them.
- **Spec, test plan and plan per change: framework right to refuse.** The top DoR failure facet is `cross_artifact_consistency` (10 of 40 FAILs), and GH-144 had to force sequential authoring to reduce it. INFERRED: much of the gate's yield is catching contradictions among documents that exist only because of the process. A Done Contract with `Check:` commands avoids that class.
- **Copy-in distribution: ADOS is right.** A global clone, local sync, and a plugin all beat tree copying, with caveats in section 6.
- **18 skills, long AGENTS.md: ADOS is the warning.** 44 prompt files and a 308-line AGENTS.md need a `@toolsmith` agent and guards just to stay consistent. A small surface is an asset; 18 should shrink.
- **Living system spec (`doc/spec/**`, phase 7): undecided.** It gives agents a current baseline, but it costs a phase per change and an 876-line command. `spec-coverage-snapshot.sh` only counts files. Not proven; do not adopt without measurement.
- **Tickets as the unit of work: both agree.** ADOS uses tracker tickets with a git artifact folder, which fits orchestrators better than local numbering. Keep markdown tickets as the default and add an external ID.

## 4. Delete or simplify

- Delete `tracker`, `limits.exception_max_days` and `models.*` unless a real tracker seam is built. ADOS shows the seam is small: normalized `{state, labels}` behind one function (`deliver-ticket.sh:301-372`).
- Replace `limits.stop_followups` and the stop hook's loop with the "clean exit is terminal" rule, since re-prompting is what cost ADOS tokens. Supervising belongs outside the agent.
- Drop the test ratchet in its local-stamp form. Mutation tests give stronger evidence for the framework's own code, and host test counts belong in CI.
- Move framework docs out of the project tree via a distribution marker instead of asking each project to delete them.
- Do not add phases, role agents, or a decision-record taxonomy. ADOS's 53 templates and five record types are what to avoid.

## 5. Orchestration

- **Plug-in shape works.** `deliver-ticket.sh` is a blocking, idempotent, join-safe unit of dispatch that returns a machine summary. Comments show an external consumer ("fork-join", "lanes", `ADOS_ENV_FILE` for service managers, `:82-91`, `:2078`). The framework needs the same: `run NN` blocks, is safe to repeat, and returns structured output. Today `advance` is close but has no runner, no join, no JSON.
- **Separate cheap supervision from expensive judgment.** The agent makes decisions at points; a script waits. Never let an agent poll or detach (`INV-DM-1`).
- **Query, do not read state files.** `--is-delivering`, `--status`, `--last-message`, and `ceo.md`'s ban on reading PID files keep state private.
- **Distinguish failure types for dispatchers.** `partial` (resume), `noop-lane-permission` (fix prompt), `noop-lane-nothing-to-do` (close), `state-unverified` (investigate). Each maps to a different caller action.
- **Runtime coupling is the main lesson in reverse.** The supervisor is tied to OpenCode's CLI and database. A framework that "plugs into orchestrators" must define a small agent-runner interface first.
- **Parallelism is unsolved.** One ticket per worktree, and clones cannot see each other (`delivery-modes.md:440-447`), so two clones can take the same ticket. A claim must be a pushed ref or a tracker assignment.
- **Standalone use.** Mode B (human lists tickets, human approves, script merges) is the safest first unattended mode and fits the framework's HIGH rule.

## 6. Do not copy

- **`@ceo` authority.** Self-approval, CI waivers, and circuit breakers that exist only as prompt text: 100 merges per session (`ceo.md:338`), a counter in a memory schema (`:209`), and "does not modify ceo.md" (`:332`). No script reads them (VERIFIED by grep).
- **Trusting agent-written completion.** `artifact_pm_notes_complete` reads only `delivery.completed`, phase 6 of 11 (`:1456-1516`), so `finished` exit 0 can precede any review. The ADOS review artifact has the framework's forged-critic hole and worse: nothing checks that it exists. ADOS offers no fix for the self-written-report gap.
- **Bugs in classification.**
  - A clean exit classified `failed` with no artifact verdict falls to `*) stop:0:finished` (`:1645`), breaking its own exit rule (read, not run).
  - A Jira ticket that is "Cancelled" or "Won't do" maps to closed, then to `merged` (`:340`, `:1321`).
  - The blocked label uses a substring grep (`:1328`), while `approved` is exact.
  - `wait_for_pr_green` greps text; ASSUMED: `gh pr checks` exits non-zero when pending or failing, so that path would park rather than wait.
- **Install gaps.** `curl | bash` from `main`, no version recorded in the project, updatable files overwritten without warning by default (`install.sh:311-316`), and scripts copied into the host's `scripts/` and `tools/`, the same collision the framework has. `uninstall.sh:69-82` hard-codes lists that lack `ceo.md`, `readiness-reviewer.md`, and three commands, so global uninstall leaves them.
- **History in shipped files.** 56 of 113 `redistributable` docs cite GH/PDEV refs; `deliver-ticket.sh` has 108 lines with internal IDs. The "current-state prompts" rule (AGENTS.md) is good but covers prompts only.
- **Secrets on argv.** `curl -u user:token` is visible in the process list (`:326`). `opencode.jsonc` uses unpinned `npx -y`.
- **Scope creep.** `tools/text-to-image` (2,979 lines, more in tests), `zclaude`, meeting and image agents. Best review findings came from `@red-team-coordinator`, cited in 11 files (19 lines in change docs) but not shipped, so the published gate is weaker than the one that produced the record.
- **Suspicious content.** No injection aimed at readers found. `ceo.md` deliberately tells an agent to override human-only gates; quoted above as a design risk, not an attack.

## 7. If you rebuilt the framework

Keep the core: `compute_next`, script-owned state, hooks, Done Contract checks, three lanes. Change the outer shape to three layers. A kernel of gate, ledger and hooks in a versioned payload outside the host's `scripts/`, with manifest and distribution classes. A `run` supervisor in python3 with an agent-runner interface, single-flight, liveness, the evidence ladder, and one JSON result schema. A policy file that states who accepts and who merges per tier and mode. Authority and identity move to the forge where available (required checks, protected review, pushed claim refs), with local markdown as the offline default. Prove it with mutation tests and a script-written event log, not more phases.
